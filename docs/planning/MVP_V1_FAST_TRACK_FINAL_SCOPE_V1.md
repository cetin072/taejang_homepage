# 태장 업무플랫폼 MVP 1차 빠른 완성 범위 v1

상태: **확정**  
확정일: 2026-07-30

## 1. 목적

태장 업무플랫폼의 전체 장기 기획은 유지한다. 다만 첫 번째 실제 사용 가능 버전은 새 기능을 넓히지 않고, 이미 구현된 인증·권한·일반 근로자 정보게시판을 비운영 Supabase staging과 연결해 제한된 사용자가 끝까지 써볼 수 있게 만드는 데 집중한다.

이 문서는 기존 `MVP_FUNCTIONAL_SPECIFICATION_V1.md`를 대체하지 않는다. 현재 제작 우선순위와 첫 시범운영의 완료 기준을 고정한다.

## 2. 이미 확보된 기반

- 회원가입·로그인·승인 대기·역할별 자동 이동
- `pending | active | suspended | departed | deleted` 계정 상태
- 마지막 활성 최고관리자 보호
- 역할·부서·직책과 RLS 기반 접근 제어
- 일반 근로자용 오늘의 업무, 작업방법, 내 일정, 중요공지, 자주 보는 안내
- 운영총괄·부서 팀장·현장 책임자의 최소 관리 화면
- 역할별 대시보드 셸과 중요 변경 감사로그
- staging 준비 도구와 QA 문서
- staging migration 6개 적용, public 테이블 17개 RLS 활성화

따라서 MVP 1차는 기초 기능을 다시 만드는 작업이 아니라 실제 연결·샘플 데이터·역할별 검수·시범운영 준비를 완료하는 작업이다.

## 3. MVP 1차 필수 범위

### 계정과 권한

- `/staff/` 회원가입·로그인
- 신규 계정 `pending`
- 최고관리자의 부서·직책·역할 배정과 `active` 승인
- 비로그인·승인 대기·정지·퇴사·삭제 계정 차단
- 최소 2명의 active 최고관리자와 마지막 최고관리자 보호 확인

### 일반 근로자 읽기 화면

- 오늘의 업무
- 작업방법
- 내 일정
- 중요공지
- 자주 보는 안내

일반 근로자에게 시작·완료·수량·실적·출퇴근·자유보고 입력을 요구하지 않는다.

### 최소 관리자 기능

운영총괄, 부서 팀장 또는 현장 책임자가 권한 범위 안에서 다음 자료를 생성·수정·게시·사용 중지할 수 있어야 한다.

- 오늘의 업무
- 작업방법
- 일정
- 중요공지
- 자주 보는 안내

### 접근·보안 검증

- 회사 전체, 현재 부서, 현재 작업반, 본인 개인 대상만 조회
- 타 부서·타 작업반·타인·초안·사용 중지·기간 밖 자료 차단
- 직접 URL, 새로고침, 뒤로가기에서도 접근 문맥 재확인
- 계정 상태 변경 후 기존 access token의 DB 요청 즉시 차단
- 가입 승인, 상태·역할 변경, 게시·사용 중지 등 중요 변경만 감사기록

### 실제 기기 검수

- 일반 근로자: 모바일 우선, 큰 글자·큰 버튼·단일 열
- 관리자: PC 우선
- 실제 모바일 1대와 PC 1대 이상에서 전체 동선 확인
- 200% 확대, 키보드 이동, 가로 스크롤, 쉬운 오류·빈 상태 확인

## 4. 지금 수행할 제작 순서

1. staging 전용 QA 가상 사용자와 최소 샘플 데이터 생성
2. 내부 업무플랫폼 브라우저 코드를 hosted staging Supabase에 연결
3. 로그인 사용자 기준 역할·대상 범위 RLS 확인
4. 관리자 입력 → 게시 → 일반 근로자 조회의 전체 흐름 확인
5. `suspended`와 `departed` 전환 후 즉시 접근 차단 확인
6. 비운영 Deploy Preview 또는 staging 주소에서 모바일·PC 수동 QA
7. 차단 오류만 수정하고 QA 결과 기록
8. 대표 승인 전 production 연결·실제 직원 데이터 입력 금지

최소 QA 역할은 최고관리자 2명, 운영총괄 1명, 부서 팀장 또는 현장 책임자 1명, 일반 근로자 1명이다.

최소 샘플 데이터는 오늘의 업무 2건, 작업방법 1건, 일정 2건, 중요공지 1건, 자주 보는 안내 2건이다.

## 5. MVP 1차 제외 범위

- 근로자지원·상담 상세기록
- 현장 작업 결과·문제·조치·인계
- 홍보업무·홈페이지 콘텐츠 승인
- 홈페이지 사진 촬영·업로드·공개동의 검증
- PHOTO 01~11 관리
- 주간 홈페이지 일괄 발행과 정적 공개 발행본 연결
- Supabase Storage 파일 업로드
- PWA 설치·푸시·완전한 오프라인
- Google API·OAuth 자동연동
- AI 작성·평가·상담판단
- 자동 크롭·보정·중복 사진 감지
- 생산실적·근태·급여·재고·ERP
- 대표이사 경영 통계와 고급 보고서

제외된 기능은 폐기한 것이 아니다.

## 6. 후속 우선순위

1. 홈페이지 콘텐츠·사진 등록, 홍보팀장 승인, 발행 대기함의 최소 MVP
2. PHOTO 01~08 고정 슬롯과 최근 활동 대표사진 관리
3. 주간 정적 발행과 마지막 정상 공개본 연결
4. 현장관리 최소기록과 작업반 운영
5. 근로자지원·고용유지 모듈
6. 대표이사·운영총괄 상세 보고와 부서 간 협업
7. 자동화·고급 이미지·외부 API

최근 논의한 홈페이지 사진 등록 기능은 MVP 1차 시범운영 직후의 첫 번째 후속 개발 대상으로 보존한다.

## 7. 완료 기준

- QA 사용자가 가입하고 승인 대기 상태를 확인함
- 최고관리자가 승인과 역할 배정을 수행함
- 역할별 허용 화면으로 자동 이동함
- 관리자가 5개 정보 유형을 작성·게시함
- 일반 근로자가 모바일에서 본인 대상 정보만 확인함
- 범위 밖·초안 자료가 노출되지 않음
- 정지·퇴사 계정의 DB 접근이 즉시 차단됨
- 마지막 최고관리자 보호가 작동함
- 실제 모바일·PC 수동 QA 완료
- 차단 등급 오류 없음
- QA 결과와 후속 항목을 GitHub 문서에 기록함
- production과 실제 직원 데이터는 대표 승인 전까지 변경하지 않음

## 8. 범위 변경 기준

새 요구가 나오면 다음을 확인한다.

> 이 기능이 없으면 staging에서 첫 번째 실제 사용 흐름을 끝까지 검증할 수 없는가?

불가능하면 MVP 1차에 포함한다. 불편하지만 검증 가능하거나 자동화·고급 편의 기능이면 후속 단계로 미룬다.

## 결정 이력

- 2026-07-30: 이미 구현된 Phase 1A와 일반 근로자 정보게시판을 hosted staging에서 연결·검증하는 것을 MVP 1차의 최우선 목표로 확정했다.
- 2026-07-30: 홈페이지 콘텐츠·사진 등록과 주간 정적 발행은 MVP 1차에서 제외하되, 시범운영 직후 첫 후속 개발 대상으로 기록했다.
