## 1. 목적과 확정 범위

직원별 근무조건을 한 번 관리하고 출근 누락 알림과 휴가 관리가 재사용한다.
직원앱에서는 남은 연차 개수만 간단히 표시하고 기존 승인된 연차 신청·처리결과 확인을 제공한다. 근무시간과 지금까지 발생한 연차·남은 연차는 관리자가 입력한다.
백엔드 웹에서는 근무조건과 연차 부여·신청 승인·휴무 현황을 관리한다.
이 문서는 기획 승인 기록이다. 구현 완료, main 병합, 운영 DB 적용, Play 배포 승인을 뜻하지 않는다.

### 목표 1: 출근 누락 알림은 1차만

- 위치를 확인하지 않고 오늘 근무시간과 서버 출근 기록을 기준으로 알림한다.
- 앱을 열었는지가 아니라 출근 기록이 없는지가 판단 기준이다.
- 근무시간이 되어도 위치를 모르므로 회사 밖에서도 받을 수 있다.
- 위치 기반 2차는 이번 범위에서 제외한다. 백그라운드 위치 권한·지오펜싱·상시 위치수집을 추가하지 않는다.
- 자동 출근·자동 결근 확정·급여 불이익 판단을 하지 않는다.
- 퇴근 알림은 기존 구현·현재 PR과 먼저 대조한다. 별도 중복 시스템을 만들지 않는다.

### 목표 2: 연차 신청·조회와 관리자 관리

- 관리자 확인 후 연차 부여·조정, 직원앱 신청, 관리자 승인·반려·취소, 사용·잔여 조회.
- 종일·반차를 지원하되 직원별 근무시간과 일관된 차감 기준을 사용한다.
- 회사 전체 휴무·개인 휴무와 유급 연차를 구분한다.
- 승인된 휴가는 근태 표시 및 알림 제외 조건에 연결한다.
- 법정 발생일수 자동계산·자동 이월·소멸·연차수당 정산은 이번 범위가 아니다.

## 2. 현재 구현과 재사용 경계

2026-11-01 main 기준:

- 기존 employees 불변 식별자, Auth↔Person↔Employee 연결, 서버 근태·확정/재개방·감사·푸시 계약을 재사용한다.
- 기존 급여 조건을 무단 복제하거나 변경하지 않는다. 근무시간 정본과 급여 조건 간 관계는 구현 전 명시한다.
- 기존 미기록 알림 작업 #571 및 후속 Issue를 다시 확인해 중복을 방지한다.

## 3. 백엔드 화면

### 직원 관리 → 근무조건

- 근무요일, 시작·종료시간, 휴게시간, 하루 소정근로시간.
- 기본 근무장소 선택 및 적용 시작일·종료일, 변경 사유.
- 날짜별 외근/현장·시간 변경, 휴일근무 등 예외.
- 과거 근무조건을 현재 값으로 덮어쓰지 않고 적용일별 이력을 보존한다.
- 장소는 기존 출근 허용장소 구조를 우선 재사용한다. 이름·위치·허용반경 변경이 실제 출근 허용범위를 바꾸는 경우 기존 권한/승인 경계를 유지한다.
- 여러 장소를 관리할 수 있어도 직원 등록 시 임의 장소에 자동 배정하지 않는다.

### 별도 메뉴 → 연차·휴무 관리

- 직원별 연차대장: 기준기간, 부여·조정·사용·취소 내역, 승인 대기와 사용 가능한 잔여.
- 신청 처리: 날짜·종일/반차·상태·처리자·처리시각·처리 사유.
- 휴무: 회사 공통/개인별 휴무와 연차를 구분.
- 현황: 날짜별 휴가자·예정 근무자, 필요 범위의 목록/간단한 달력.
- 근무시간과 지금까지 발생한 연차·남은 연차 개수는 관리자가 입력한다. 직원앱에서는 입력·수정할 수 없다.
- 최초 잔여는 기준일 현재 남은 개수로 등록한다. 최초 부여 총량으로 오인해 과거 사용분을 다시 차감하지 않는다.
- 최초 잔여 입력에는 기준일·입력 근거를 남겨 기존 수기 사용내역과 이중 차감하지 않는다. 필요하면 과거 사용분은 별도 근거로 관리하며 최초 잔여와 중복 계산하지 않는다.
- 미입력은 0개로 간주하지 않고 ‘관리자 등록 대기’로 표시하며 신청 가능 잔여를 추정하지 않는다.

## 4. 직원앱

- 내 연차: ‘남은 연차 N일’만 간단히 표시한다. 부여·사용·예약·조정 상세는 관리자 화면에 둔다.
- 관리자 입력 최초 잔여를 기준으로 이후 승인 사용분·취소·조정을 서버에서 계산한다. 승인 대기분 예약을 반영한 신청 가능 잔여를 표시하며 서버 검증과 일치시킨다.
- 직원앱에는 근무시간·최초 잔여·연차 조정 입력 기능을 제공하지 않는다.
- 신청: 날짜 → 종일/반차 → 제출. 여러 날짜는 해당 근무일만 일관되게 산정한다.
- 내 신청: 승인 대기·승인·반려·취소 상태 및 처리결과.
- 중복 탭으로 신청을 중복 생성하지 않는다.
- 타 직원의 연차·사유·잔여는 노출하지 않는다.
- 실패 시 선택 날짜와 입력을 보존하고 재시도할 수 있게 한다.
- 변경되는 사용자 동작은 같은 구현 PR의 모바일 패치노트에 기록한다.

### 연차 신청 기한 (확정)

- 종일·반차 모두 사용일 최소 3일 전에 신청해야 한다.
- 달력 날짜 기준(주말·공휴일 포함), Asia/Seoul 서버 날짜로 판단한다. 72시간 단위로 계산하지 않는다.
- 신청 가능 조건: 사용일 >= 서버의 오늘(KST) + 3일.
- 예: 11월 10일 사용분은 11월 7일 23:59:59 KST까지 신청 가능. 11월 8일부터 신청 불가.
- 당일·다음 날·이틀 뒤 및 지난 날짜의 신규 연차 신청은 차단한다.
- 여러 날짜를 한 번에 신청하면 모든 사용일이 조건을 만족해야 하며, 위반 날짜를 알리고 전체 제출을 거부한다.
- 날짜를 변경하거나 취소 후 재신청할 때도 제출 시점에 다시 검증한다. 임시저장 날짜로 기한을 우회할 수 없다.
- 앱에서 신청 불가 날짜와 이유를 안내하고, 서버 RPC에서 같은 조건을 최종 검증한다. 휴대폰 시각 변경·직접 API 호출로 우회 불가.
- 안내: “연차는 사용일 최소 3일 전에 신청할 수 있습니다.”
- 별도의 기한 예외 승인이나 관리자 대리 신청 우회는 이번 결정으로 허용하지 않는다. 기존 근태 수기 보정은 연차 신청과 구분한다.

## 5. 상태·일수·데이터 보존

- 신청 상태: 승인 대기 → 승인 / 반려 / 취소.
- 승인 후 취소는 근태 확정 여부와 연동하고 기록을 삭제하지 않는다.
- 잔여 숫자만 덮어쓰지 않는다. 부여·사용·취소·조정의 근거를 보존한다.
- 대기 신청은 별도 예약량으로 표시해 중복 신청을 막는다. 승인 시 예약 해제와 사용 반영을 원자적으로 처리한다.
- 같은 직원의 동시 신청·승인에서도 초과 사용과 중복 차감이 생기지 않아야 한다.
- 취소/반려 시 예약·사용 복구는 한 번만 적용한다.
- 근태 확정일은 기존 재개방 절차 없이 수정하지 않는다. 연차 승인만 되고 근태가 누락되는 부분 성공을 방지한다.
- 기존 출근 기록과 휴가가 충돌하면 자동 삭제/덮어쓰지 않고 명시적으로 처리한다.
- 과거 기록은 당시의 근무조건·차감 근거로 보존한다.
- 연차를 수기 유급휴가로 지정한 기존 내역은 자동으로 연차대장 사용분이라고 간주하지 않는다.
- 상세 건강정보·진단명·불필요한 증빙을 기본 수집하지 않는다.

## 6. 출근 누락 알림

판단 순서:
1. 활성 재직자이며 근태 대상인가?
2. 적용일 기준 유효 근무조건과 오늘 근무 일정이 있는가?
3. 승인 연차·휴무·휴직 등 제외일인가? 반차이면 실제 근무 시작시간을 적용할 수 있는가?
4. 서버에 출근 또는 처리된 예외 기록이 있는가?
5. 알림 가능 시간대·중복/재알림 조건을 만족하는가?
6. 기존 푸시 전송 구조로 알림한다.

- 근무조건이 없거나 충돌하는 경우 임의로 09시 등 기본값을 추정하지 않는다. 관리자에게 미설정으로 표시한다.
- 알림 생성 직전 출근·휴가 상태를 재확인한다.
- 직원·근무일·알림종류·회차 기준 중복 방지.
- 실패·재시도·토큰 만료와 발송 시도/전달 확인을 구분한다.
- 알림 권한 꺼짐 또는 미수신을 결근으로 해석하지 않는다.
- 잠금화면에는 휴가 사유·민감정보를 담지 않는다.
- 알림을 누르면 출근 화면으로 이동하되 기존 출근 위치 검증은 그대로 수행한다.
- 새 예약 실행/사용량 확대/운영 설정은 기존 배포 및 승인 범위와 대조한다.

## 7. 권한·업무규칙

확정:
- 직원은 자신의 연차 및 신청만 조회·신청한다.
- 관리자만 연차 부여·조정·신청 결정을 할 수 있다.
- 서버에서 실제 계정·직원 연결·활성상태·업무권한을 재검증한다.
- 메뉴 노출만으로 권한을 허용하지 않는다.
- 모든 변경은 행위자·시각·사유를 남기고 다른 직원의 데이터 접근을 차단한다.

검토 중 (임의 확정 금지):
- 운영총괄 최종 승인인지, 운영팀장 처리/상신을 허용할지 등 정확한 승인선.
- 본인 신청의 자기승인 및 대리 신청/대리 승인 처리 기준.
- 최초 잔여의 기준일·실제 값·기간/이월분의 처리. 관리자 최초 입력 방식은 확정이며 실제 직원별 값은 임의 생성하지 않는다.
- 반차 구분 및 홀수/짧은 근무시간 직원의 시간 단위·차감 기준.
- 승인 후 취소의 허용 시점.
- 알림 최초 발송 시점과 재알림 횟수·간격.
위 미정 항목은 화면·데이터·기본 흐름 검토를 막지 않지만 운영 자동처리 기본값으로 가정하지 않는다.

## 8. 순서와 검수

1. 근무조건 입력·유효기간·이력.
2. 관리자 연차대장과 직원앱 신청·잔여 조회·관리자 처리.
3. 승인 휴가와 근태 연결, 휴가 제외 조건을 반영한 시간 기준 출근 알림.

필수 검수:
- 3시간→4시간 월중 변경과 입퇴사·휴직 경계.
- 주말·공휴일·외근·임시시간·휴일근무 예외.
- 연차 없는 직원, 미설정 근무조건, 부족 잔여, 겹치는 날짜.
- 신청일 +3일 허용, +2일·당일·과거 차단, KST 자정 경계, 주말·공휴일 포함, 종일/반차, 다일 신청, 날짜 변경·재신청, 직접 API 우회 차단.
- 동시 신청·승인·취소와 재시도에서 중복 차감 없음.
- 반차일 근무시간 및 알림 제외 범위.
- 확정 근태 충돌과 실패 시 원본·입력 보존.
- 실제 Auth/서버 권한 교차계정 차단. 격리 DB로 검증하며 실직원 데이터는 변경하지 않음.
- 알림 중복·출근 직후 경합·권한 꺼짐·만료 토큰.
- 웹 PC/모바일 및 직원앱의 실제 신청→승인→재조회 흐름.
- main 병합/운영 DB·배포/Play 반영은 별도 승인.

- 첫 알림은 직원/근무일/출근·퇴근 종류별 이벤트 1개, 기기별 전달 1개. 반복 횟수·간격은 미정이므로 정기 독촉을 만들지 않는다. 발송 불명 결과는 재발송하지 않는다.

- 정책 5분은 확정하되 enabled=false 및 Edge OFF를 보존한다. 운영 migration/배포·스케줄·실기기 검증은 별도 단계다.
- 이 절이 알림 최초 시점 미확정인 이전 문구보다 우선한다. 승인 후 취소·급여 등 다른 미확정 사항은 유지한다.


## 16. 연차 업무 중심 관리자 화면 (2026-11-02)

## 17. 확정 연차 출근부 선반영·직원 취소/수정 (2026-11-02)

사용자 확정: 승인된 연차는 미래 사용일 출근부에 즉시 연차로 표시한다. 직원은 앱에서 취소/수정하며 승인 후 변경은 관리자 재승인을 받는다. 승인 전에는 여러 번 수정 가능하고, 승인 후 일정 수정 요청만 사용일 전까지 1회로 제한한다. 반복 실수·중복 조작 방지가 목적이다.

- 승인 전 수정은 기존 예약을 원자적으로 대체한다. 실패하면 원래 예약을 유지한다. 1회 제한에 포함하지 않는다.
- 승인 후 수정/취소 요청은 기존 연차·출근부·잔여를 그대로 둔다. 운영총괄/운영팀장이 승인하면 복구·신규 차감·출근부를 한 트랜잭션으로 갱신한다. 반려 시 기존 일정 유지. 자기승인은 금지한다.
- 승인 후 수정은 요청 접수 시 1회를 사용하며 반려되어도 복원하지 않는다. 승인으로 새 신청 ID가 생겨도 횟수를 승계한다. 두 번째 요청은 앱 안내 및 RPC에서 차단한다. 동일 ID/내용 재시도는 추가 횟수로 세지 않는다. 취소 요청은 수정 횟수 제한과 구분한다.
- 취소/수정 변경 승인은 원래 사용일 전까지만 가능하다. 사용일 당일/과거는 관리자 상담 후 기존 근태 재개방 절차로 처리한다. 확정 근태·이미 기록된 출퇴근과 충돌하면 임의 변경하지 않는다.
- 변경 날짜는 KST 달력 기준 요청일+3일 이상이어야 한다. 이미 기한을 충족해 접수된 요청의 관리 승인일을 새 신청일로 간주하지 않는다.
- 다일 신청은 날짜별로 취소/수정한다. 출근부는 승인 연차/앞·뒤 반차를 구분하며 반차의 남은 근무시간·알림 projection을 재사용한다.
- 운영 적용은 별도 승인 범위이며 QA 빌드·격리 검증과 구분한다.


## 18. 실사용 UI 수정 (2026-11-02)

사용자 검수: 홈 연차 진입 버튼이 작고 신청 설명이 길다. 직원관리에는 근무시간 등록만 남기고 중복 연차 기능을 제거한다. 날짜/시간을 직접 입력시키지 않으며 근무조건 저장 오류를 수정한다.

- 직원관리: 근무시간·장소·요일·휴게 등록/이력만 표시. 연차 잔여·등록·조정·신청은 연차 관리에만 둔다.
- 날짜는 달력, 시간은 기존 근태보정의 24시간 시/분 선택 패턴을 재사용한다. 역순/불완전 휴게/요일 미선택은 전송 전에 안내하고 입력을 유지한다. 기존 이력을 덮어쓰지 않도록 다음 적용 가능일을 제시한다.
- 앱 홈은 큰 연차 신청 버튼과 잔여, 신청 내역 진입으로 구성한다. 신청 화면은 날짜·종일/반차·확인 버튼에 집중하고 긴 규칙은 접는다.
- QA 기본 체험에서도 별도 예시 카드와 신청 화면을 보여주되 서버 연차를 조회/저장하지 않는다. 실제 모드는 기존 인증/서버 규칙을 그대로 사용한다.
- DB·권한·3일 신청/승인 후 수정횟수 규칙을 변경하지 않는다.

- 추가 검수: 하루 신청/여러 날 신청을 먼저 고른다. 선택 상태는 체크·문구·개수로 구분하며 여러 날에는 날짜 목록·총 일수·사용 연차 개수를 표시한다. 확인창과 최종 버튼에도 일수를 반복해 표시한다. 여러 날짜는 서버 근무일 판단을 복제하지 않고 달력에서 각각 선택한다.

- 하루 신청은 녹색, 여러 날 신청은 파란색으로 구분하되 색상에만 의존하지 않는다. 체크·‘하루/총 N일’ 문구·날짜 목록·최종 일수 확인을 함께 제공한다.


## 19. 직원앱 반차 선택 제외 (2026-11-02)

사용자 결정: 현재 장애인 직원은 3~4시간 근무하며 반차를 운영하지 않으므로 불필요한 신청 메뉴를 제외한다.

- 신규 직원앱 신청은 날짜만 선택하며 하루당 연차 1개를 사용한다. 하루/여러 날과 일수 확인은 유지한다.
- 종일/앞 반차/뒤 반차 선택 및 반차 설명을 신청 화면에서 제거한다. 근무시간을 기준으로 법적 결론을 자동 판단하는 규칙은 추가하지 않는다.
- 기존 반차 신청/승인/차감 이력은 유지한다. 기존 반차 일정 변경은 관리자 문의를 안내하고 취소 경로는 유지한다. 숨겨진 반차를 하루로 자동 변환하지 않는다.
- 이번 변경은 현재 직원앱의 신청 UI다. 과거 자료와 서버 반차 계산·조회 계약을 삭제하거나 운영 DB를 일괄 수정하지 않는다.


## 20. 근무시간 최초 등록 실사용 오류 수정 (2026-11-02)

- 기존 직원에게 근무시간을 처음 등록할 수 있어야 한다. 과거 출근 기록은 수정하지 않는다. 기본 적용일은 서버 날짜의 다음 날로 제시하며, 기존 근무시간 이력이 있으면 그 이후 날짜를 사용한다. 달력에서는 서버가 허용하는 오늘/미래 날짜를 직접 선택할 수 있다.
- 적용 당일 출근 기록이 있으면 기존 서버의 충돌 방지는 유지한다. 원본 확인만 요구하던 오류를 ‘이미 출근 기록이 있으므로 출근 기록 없는 다음 날짜 선택’ 안내로 구체화하고 모든 입력을 보존한다. 자동 날짜 변경/재전송하지 않는다. 최초 사유는 ‘최초 등록’으로 미리 표시한다.
- 모바일 근무요일은 네 칸씩 두 줄, 넓은 화면은 일곱 칸으로 배치한다. 각 요일의 체크/글자/터치 영역을 분리한다. 실제 App Shell과 admin-authoring 스타일을 포함한 브라우저 fixture에서 320/390/786/1440px의 영역 겹침·첫 등록·충돌·재시도를 검증한다.
- UI 수정이며 서버 권한·확정 근태 재개방·기존 근태 충돌 규칙을 완화하지 않는다. 운영 DB 변경 없음.


## 21. 연차관리 재직 직원·직급별 선택 및 출근부 검증 (2026-11-02)

- 기본 직원 선택은 직원관리와 같은 active/leave 재직 상태를 사용한다. 입사 전·퇴사일 경과 직원은 제외하며 휴직 중은 명시한다. 기존 직원관리의 직급 정렬 함수를 재사용하고 optgroup으로 직급별 표시한다. 최초 잔여 등록·신청 필터·예외 휴무 대상에 같은 기준을 적용한다.
- 퇴직자는 신규 잔여 등록 기본 선택에서 제외한다. 신청·승인 화면에서 ‘퇴직자 과거 신청 보기’를 선택하면 기록을 확인할 수 있다. 기존 신청/원장/퇴직 정보를 삭제하지 않는다.
- 기존 관리자 context 권한을 유지하며 재직 상태·직급·입퇴사일과 직급 순서만 추가한다. 급여·신원 민감정보는 추가하지 않는다. 구형 서버에서 상태를 추정하거나 전체 직원을 다시 표시하지 않고 업데이트 필요를 안내한다.
- 앱 신청→관리자 승인→미래 날짜의 실제 근태 조회 RPC→월간 출근부 ‘연차(승인)’, 취소 승인→‘근무 예정’ 복구를 같은 격리 TEST 직원으로 검증한다.
- 공유 서버는 기본 승인/근태 projection 존재를 읽기 전용 확인했다. PR573 취소·수정 migration은 미적용이다. 신규 roster metadata migration 역시 개발 파일이며 운영 적용하지 않는다. 이번 UI는 해당 서버 metadata 적용 후 사용 가능하다. 병합/운영 DB 반영/배포는 별도 승인 경계를 따른다.


## 23. 근무시간 등록 권한과 메뉴 책임 (2026-11-03)

- 직원관리에는 근무요일·출퇴근시각·휴게·장소와 적용일 이력만 입력한다. 연차 개수 최초 등록·조정/대장과 신청·승인은 기존 별도 연차관리 메뉴에 둔다. 같은 잔여값을 직원관리에도 중복 입력하지 않는다.
- 사용자 추가 승인: 홍보팀장(현재 운영팀장 표시인 기존 promotion_lead 역할)도 직원관리에서 근무시간을 등록·변경할 수 있어야 한다. 다른 급여·민감 인사 권한을 추가하지 않는다.
- 기존 employee.work_terms_manage 역할 부여를 재사용하되, 최초 연차 등록/잔여 조정 RPC는 operations_manager 역할과 해당 capability를 모두 검사한다. 기존 근무시간 capability를 공유했다는 이유로 연차 개수 수정까지 허용하지 않는다.
- UI는 can_manage_work_terms와 can_initialize를 구분한다. 서버가 최종 권한을 판단한다. 기존 메뉴/개인 권한 거부를 해제하지 않는다.
- 전체 흐름과 검증 경계는 docs/operations/WORK_TERMS_LEAVE_FLOW.md를 따른다. 월별 정기 실행과 실직원 알림 활성화, 물리 QA APK 수신은 이번 권한 변경의 완료 주장에 포함하지 않는다.
