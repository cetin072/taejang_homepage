상태: 기능 범위 확정 / 세부 업무규칙 일부 검토 중 / 구현 전

## 1. 목적과 확정 범위

직원별 근무조건을 한 번 관리하고 출근 누락 알림과 휴가 관리가 재사용한다.
직원앱에서는 남은 연차 개수만 간단히 표시하고 기존 승인된 연차 신청·처리결과 확인을 제공한다. 근무시간과 지금까지 발생한 연차·남은 연차는 관리자가 입력한다.
백엔드 웹에서는 근무조건과 연차 부여·신청 승인·휴무 현황을 관리한다.
이 문서는 기획 승인 기록이다. 구현 완료, main 병합, 운영 DB 적용, Play 배포 승인을 뜻하지 않는다.

### 목표 1: 출근 누락 알림은 1차만

- 위치를 확인하지 않고 오늘 근무시간과 서버 출근 기록을 기준으로 알림한다.
- 앱을 열었는지가 아니라 출근 기록이 없는지가 판단 기준이다.
- 근무시간이 되어도 위치를 모르므로 회사 밖에서도 받을 수 있다.
- 위치 기반 2차는 이번 범위에서 제외한다. 백그라운드 위치 권한·지오펜싱·상시 위치수집을 추가하지 않는다.
- 자동 출근·자동 결근 확정·급여 불이익 판단을 하지 않는다.
- 퇴근 알림은 기존 구현·현재 PR과 먼저 대조한다. 별도 중복 시스템을 만들지 않는다.

### 목표 2: 연차 신청·조회와 관리자 관리

- 관리자 확인 후 연차 부여·조정, 직원앱 신청, 관리자 승인·반려·취소, 사용·잔여 조회.
- 종일·반차를 지원하되 직원별 근무시간과 일관된 차감 기준을 사용한다.
- 회사 전체 휴무·개인 휴무와 유급 연차를 구분한다.
- 승인된 휴가는 근태 표시 및 알림 제외 조건에 연결한다.
- 법정 발생일수 자동계산·자동 이월·소멸·연차수당 정산은 이번 범위가 아니다.

## 2. 현재 구현과 재사용 경계

2026-11-01 main 기준:
- 직원 관리 입력: 이름·입사일·부서·직책·재직상태·퇴사일·근태대상. 근무조건 입력은 없음.
- payroll_employment_terms에 적용기간과 daily_scheduled_hours가 있으나 급여 도메인이다.
- attendance-admin의 paid_leave/유급휴가·월차 지정 및 휴일근무 지정은 존재한다.
- 별도 연차대장·직원앱 연차 신청·잔여 관리 메뉴는 없음.
- 기존 employees 불변 식별자, Auth↔Person↔Employee 연결, 서버 근태·확정/재개방·감사·푸시 계약을 재사용한다.
- 기존 급여 조건을 무단 복제하거나 변경하지 않는다. 근무시간 정본과 급여 조건 간 관계는 구현 전 명시한다.
- 기존 미기록 알림 작업 #571 및 후속 Issue를 다시 확인해 중복을 방지한다.

## 3. 백엔드 화면

### 직원 관리 → 근무조건

- 근무요일, 시작·종료시간, 휴게시간, 하루 소정근로시간.
- 기본 근무장소 선택 및 적용 시작일·종료일, 변경 사유.
- 날짜별 외근/현장·시간 변경, 휴일근무 등 예외.
- 과거 근무조건을 현재 값으로 덮어쓰지 않고 적용일별 이력을 보존한다.
- 장소는 기존 출근 허용장소 구조를 우선 재사용한다. 이름·위치·허용반경 변경이 실제 출근 허용범위를 바꾸는 경우 기존 권한/승인 경계를 유지한다.
- 여러 장소를 관리할 수 있어도 직원 등록 시 임의 장소에 자동 배정하지 않는다.

### 별도 메뉴 → 연차·휴무 관리

- 직원별 연차대장: 기준기간, 부여·조정·사용·취소 내역, 승인 대기와 사용 가능한 잔여.
- 신청 처리: 날짜·종일/반차·상태·처리자·처리시각·처리 사유.
- 휴무: 회사 공통/개인별 휴무와 연차를 구분.
- 현황: 날짜별 휴가자·예정 근무자, 필요 범위의 목록/간단한 달력.
- 근무시간과 지금까지 발생한 연차·남은 연차 개수는 관리자가 입력한다. 직원앱에서는 입력·수정할 수 없다.
- 최초 잔여는 기준일 현재 남은 개수로 등록한다. 최초 부여 총량으로 오인해 과거 사용분을 다시 차감하지 않는다.
- 최초 잔여 입력에는 기준일·입력 근거를 남겨 기존 수기 사용내역과 이중 차감하지 않는다. 필요하면 과거 사용분은 별도 근거로 관리하며 최초 잔여와 중복 계산하지 않는다.
- 미입력은 0개로 간주하지 않고 ‘관리자 등록 대기’로 표시하며 신청 가능 잔여를 추정하지 않는다.

## 4. 직원앱

- 내 연차: ‘남은 연차 N일’만 간단히 표시한다. 부여·사용·예약·조정 상세는 관리자 화면에 둔다.
- 관리자 입력 최초 잔여를 기준으로 이후 승인 사용분·취소·조정을 서버에서 계산한다. 승인 대기분 예약을 반영한 신청 가능 잔여를 표시하며 서버 검증과 일치시킨다.
- 직원앱에는 근무시간·최초 잔여·연차 조정 입력 기능을 제공하지 않는다.
- 신청: 날짜 → 종일/반차 → 제출. 여러 날짜는 해당 근무일만 일관되게 산정한다.
- 내 신청: 승인 대기·승인·반려·취소 상태 및 처리결과.
- 중복 탭으로 신청을 중복 생성하지 않는다.
- 타 직원의 연차·사유·잔여는 노출하지 않는다.
- 실패 시 선택 날짜와 입력을 보존하고 재시도할 수 있게 한다.
- 변경되는 사용자 동작은 같은 구현 PR의 모바일 패치노트에 기록한다.

### 연차 신청 기한 (확정)

- 종일·반차 모두 사용일 최소 3일 전에 신청해야 한다.
- 달력 날짜 기준(주말·공휴일 포함), Asia/Seoul 서버 날짜로 판단한다. 72시간 단위로 계산하지 않는다.
- 신청 가능 조건: 사용일 >= 서버의 오늘(KST) + 3일.
- 예: 11월 10일 사용분은 11월 7일 23:59:59 KST까지 신청 가능. 11월 8일부터 신청 불가.
- 당일·다음 날·이틀 뒤 및 지난 날짜의 신규 연차 신청은 차단한다.
- 여러 날짜를 한 번에 신청하면 모든 사용일이 조건을 만족해야 하며, 위반 날짜를 알리고 전체 제출을 거부한다.
- 날짜를 변경하거나 취소 후 재신청할 때도 제출 시점에 다시 검증한다. 임시저장 날짜로 기한을 우회할 수 없다.
- 앱에서 신청 불가 날짜와 이유를 안내하고, 서버 RPC에서 같은 조건을 최종 검증한다. 휴대폰 시각 변경·직접 API 호출로 우회 불가.
- 안내: “연차는 사용일 최소 3일 전에 신청할 수 있습니다.”
- 별도의 기한 예외 승인이나 관리자 대리 신청 우회는 이번 결정으로 허용하지 않는다. 기존 근태 수기 보정은 연차 신청과 구분한다.

## 5. 상태·일수·데이터 보존

- 신청 상태: 승인 대기 → 승인 / 반려 / 취소.
- 승인 후 취소는 근태 확정 여부와 연동하고 기록을 삭제하지 않는다.
- 잔여 숫자만 덮어쓰지 않는다. 부여·사용·취소·조정의 근거를 보존한다.
- 대기 신청은 별도 예약량으로 표시해 중복 신청을 막는다. 승인 시 예약 해제와 사용 반영을 원자적으로 처리한다.
- 같은 직원의 동시 신청·승인에서도 초과 사용과 중복 차감이 생기지 않아야 한다.
- 취소/반려 시 예약·사용 복구는 한 번만 적용한다.
- 근태 확정일은 기존 재개방 절차 없이 수정하지 않는다. 연차 승인만 되고 근태가 누락되는 부분 성공을 방지한다.
- 기존 출근 기록과 휴가가 충돌하면 자동 삭제/덮어쓰지 않고 명시적으로 처리한다.
- 과거 기록은 당시의 근무조건·차감 근거로 보존한다.
- 연차를 수기 유급휴가로 지정한 기존 내역은 자동으로 연차대장 사용분이라고 간주하지 않는다.
- 상세 건강정보·진단명·불필요한 증빙을 기본 수집하지 않는다.

## 6. 출근 누락 알림

판단 순서:
1. 활성 재직자이며 근태 대상인가?
2. 적용일 기준 유효 근무조건과 오늘 근무 일정이 있는가?
3. 승인 연차·휴무·휴직 등 제외일인가? 반차이면 실제 근무 시작시간을 적용할 수 있는가?
4. 서버에 출근 또는 처리된 예외 기록이 있는가?
5. 알림 가능 시간대·중복/재알림 조건을 만족하는가?
6. 기존 푸시 전송 구조로 알림한다.

- 근무조건이 없거나 충돌하는 경우 임의로 09시 등 기본값을 추정하지 않는다. 관리자에게 미설정으로 표시한다.
- 알림 생성 직전 출근·휴가 상태를 재확인한다.
- 직원·근무일·알림종류·회차 기준 중복 방지.
- 실패·재시도·토큰 만료와 발송 시도/전달 확인을 구분한다.
- 알림 권한 꺼짐 또는 미수신을 결근으로 해석하지 않는다.
- 잠금화면에는 휴가 사유·민감정보를 담지 않는다.
- 알림을 누르면 출근 화면으로 이동하되 기존 출근 위치 검증은 그대로 수행한다.
- 새 예약 실행/사용량 확대/운영 설정은 기존 배포 및 승인 범위와 대조한다.

## 7. 권한·업무규칙

확정:
- 직원은 자신의 연차 및 신청만 조회·신청한다.
- 관리자만 연차 부여·조정·신청 결정을 할 수 있다.
- 서버에서 실제 계정·직원 연결·활성상태·업무권한을 재검증한다.
- 메뉴 노출만으로 권한을 허용하지 않는다.
- 모든 변경은 행위자·시각·사유를 남기고 다른 직원의 데이터 접근을 차단한다.

검토 중 (임의 확정 금지):
- 운영총괄 최종 승인인지, 운영팀장 처리/상신을 허용할지 등 정확한 승인선.
- 본인 신청의 자기승인 및 대리 신청/대리 승인 처리 기준.
- 최초 잔여의 기준일·실제 값·기간/이월분의 처리. 관리자 최초 입력 방식은 확정이며 실제 직원별 값은 임의 생성하지 않는다.
- 반차 구분 및 홀수/짧은 근무시간 직원의 시간 단위·차감 기준.
- 승인 후 취소의 허용 시점.
- 알림 최초 발송 시점과 재알림 횟수·간격.
위 미정 항목은 화면·데이터·기본 흐름 검토를 막지 않지만 운영 자동처리 기본값으로 가정하지 않는다.

## 8. 순서와 검수

1. 근무조건 입력·유효기간·이력.
2. 관리자 연차대장과 직원앱 신청·잔여 조회·관리자 처리.
3. 승인 휴가와 근태 연결, 휴가 제외 조건을 반영한 시간 기준 출근 알림.

필수 검수:
- 3시간→4시간 월중 변경과 입퇴사·휴직 경계.
- 주말·공휴일·외근·임시시간·휴일근무 예외.
- 연차 없는 직원, 미설정 근무조건, 부족 잔여, 겹치는 날짜.
- 신청일 +3일 허용, +2일·당일·과거 차단, KST 자정 경계, 주말·공휴일 포함, 종일/반차, 다일 신청, 날짜 변경·재신청, 직접 API 우회 차단.
- 동시 신청·승인·취소와 재시도에서 중복 차감 없음.
- 반차일 근무시간 및 알림 제외 범위.
- 확정 근태 충돌과 실패 시 원본·입력 보존.
- 실제 Auth/서버 권한 교차계정 차단. 격리 DB로 검증하며 실직원 데이터는 변경하지 않음.
- 알림 중복·출근 직후 경합·권한 꺼짐·만료 토큰.
- 웹 PC/모바일 및 직원앱의 실제 신청→승인→재조회 흐름.
- main 병합/운영 DB·배포/Play 반영은 별도 승인.
