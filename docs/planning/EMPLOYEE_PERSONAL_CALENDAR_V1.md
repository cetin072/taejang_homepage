# 전 직원 기본 캘린더 V1 — 2026-11-09 사용자 승인

관련: #620. 모든 활성 직원은 직책·업무수첩 사용 여부와 무관하게 개인 캘린더를 사용한다. 운영총괄과 동일한 기존 달력 레이아웃을 재사용한다. 업무성과·업무 등록을 강제하지 않는다. 업무수첩 연동은 선택이며 같은 인증 계정의 일정은 양방향으로 사용한다.

## 단일 원본과 책임

- 개인 일정: 기존 `worklog.schedules` 한 행. ERP와 업무수첩이 같은 행을 조회/수정/취소한다. 동기화 큐·복사 테이블·주기적인 복제 없음.
- 신규 직원: 조회는 공간을 생성하지 않는다. 첫 명시적 저장에서만 본인 전용 내부 공간과 소유자 멤버십을 준비한다. 별도 Auth 계정·업무수첩 가입·업무/성과 레코드를 만들지 않는다.
- 같은 인증 계정만 연결한다. 다른 계정을 이메일로 자동 합치지 않는다.
- 기존 업무수첩의 업무 연결 일정은 기존 업무 수정 동선을 유지한다. ERP 개인 일정 편집으로 연결 업무의 제목/마감일을 불일치시키지 않는다.
- 회사 일정: 공개 대상에 해당하는 공지의 명시적인 행사 날짜 또는 연결된 공식 일정을 읽는다. 게시 기간을 행사 기간으로 추측하지 않는다. 날짜가 없는 공지는 달력에 표시하지 않는다. 연결 공지와 공식 일정 중복을 제거하고, 공지 변경·취소는 다음 조회에서 바로 반영한다.

## 데이터와 실패 경계

로그인 + 활성 Profile + 본인 소유자 공간 확인. 역할 미리보기에서는 접근 불가. 운영총괄도 다른 직원 개인 일정 조회/수정 불가. 공지·공식 일정은 읽기 전용이다. 기존 공지 공개 대상 함수를 재사용하고 초안·예약 게시·만료·보관 문서는 제외한다. 행사 취소는 달력에 취소 표시한다.

저장은 UUID 요청으로 재시도 중복을 방지한다. 수정·삭제는 `updated_at`을 확인해 다른 화면의 변경을 덮어쓰지 않는다. 충돌/통신 실패 시 입력을 유지한다. 삭제는 원본 행을 보존하는 취소다. 계정 변경/로그아웃/역할 미리보기는 이전 계정 화면과 지연 응답을 폐기한다.

종일 일정은 한국 시간 자정부터 종료일 다음날 자정까지. 날짜 범위·제목·시간 순서·길이는 RPC에서 검증한다. 회사 공지를 읽어도 자동 확인 처리하지 않는다. 별도 알림/Google Calendar/외부 계정 연결은 이 범위에 없다.

## 검증과 배포

`tests/employee-calendar-auth-integration.mjs`: 기존 CI의 일회용 로컬 Supabase에서 신규 직원, Ops 타인 차단, 활성/대기/중지/미리보기, 양쪽 REST/RPC의 동일 행 CRUD, 재시도, 동시 수정, 기간 겹침, 공지 공개/취소/대상/중복/종일 종료, 연결 업무 원본 보존을 검증한다.

`tests/helpers/employee-calendar-browser-flow.mjs`: 실제 해당 Auth/RPC와 DB를 쓰는 브라우저에서 등록→외부 수정→충돌/입력 보존→재조회→수정→삭제, 320/390/1440px, 계정 전환·미리보기·로그아웃 제거를 검증한다. 업무 API 응답을 가짜 성공으로 대체하지 않는다.

이 문서 작성 시 로컬 환경에는 Docker가 없고 Chromium 소켓 생성이 차단되어 실제 DB/브라우저 검사는 기존 GitHub CI에서 실행한다. 운영 DB 변경·main 병합·운영 배포는 이 구현 작업에 포함하지 않는다. 유료 QA 환경을 만들지 않는다. 실제 직원의 시간 절감은 아직 미측정이다.
