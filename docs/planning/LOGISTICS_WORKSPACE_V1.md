## 업무 / 권한
- 실제 활성 department_lead, promotion_lead, operations_manager, ceo: 부서 제한 없이 동일 물류 기능. 현장반장·일반 직원·시뮬레이션과 시스템 관리자 역할만 가진 계정은 불허. 다른 메뉴 권한은 변경하지 않는다.
- 청우유통은 기본 발행업체이며 단가 설정에서 변경 가능. 태장 영업·매출·회계 장부에는 자동 전기하지 않는다. 충전은 실제 입금을 확인한 후 기록하는 운영 장부이며 결제/은행/세금계산서 서비스가 아니다.
- 기본 선반 1칸 최초 3개월 무료, 추가 칸은 무료기간과 관계없이 월15,000원. 청구 시작 월차와 개월을 명시한다. 월차는 담당자가 확인해 입력하며 자동 월마감/보관 자동 청구는 이번 범위 밖이다.
- VAT 포함과 별도10% 선택. 포함은 면세가 아니다. 모든 금액은 원 정수. 수수료는 선택 사항이며 할인 반영 후 공급가액 기준.
- 확정은 견적 스냅샷 저장만 수행하며 차감은 별도 동작이다. 견적 발행 당시 고객명·단가·세액은 이후 변경하지 않는다. 변경 시 복사해 새 견적을 만든다.

## 구조
기존 ERP Shell/로그인 → 물류 메뉴(지연 로딩) → 인증된 RPC 2개 → private 스키마 고객/확정 견적/장부/단가/감사 기록. 메뉴 숨김이 보안 경계가 아니며 모든 서버 동작이 활성 계정·실제/유효 역할·시뮬레이션 여부를 재검사한다. private 함수는 필요한 권한만 부여하고 exposed public 함수는 SECURITY INVOKER다.

고객 행을 잠근 뒤 최신 잔액을 계산하고 거래/감사를 하나의 트랜잭션에 기록한다. 동일 요청 UUID는 같은 결과를 반환하며 다른 payload/actor로 재사용할 수 없다. 견적 중복 차감·잔액 부족·원거래 중복 정정을 차단한다. 장부/견적/감사 원본은 수정·삭제하지 않고 반대 거래로 정정한다. 원 견적을 정정한 뒤 재청구할 때는 새 견적을 만든다.

브라우저의 sessionStorage는 미확인 요청 UUID 보존에만 사용하고 잔액·고객의 원장이 아니다. 서버 오류 시 입력을 유지한다. 조회는 현재 고객 잔액과 거래 50건 단위 페이지이며 다른 직원의 변경은 새로고침으로 확인한다.

## 데이터 / 배포 경계
기존 HTML 로컬 장부는 사용자 브라우저에 있으며 첨부 HTML에 들어있지 않다. 이번 이식은 실제 고객·과거 충전금을 자동 이관하지 않는다. 이관은 JSON 백업 확보 → 이름/잔액/중복 대조 → 별도 승인 후 실행한다. 운영 DB에 가상 검수 거래를 쓰지 않는다.

새 migration은 기존 프로젝트의 고정 lockfile CLI로 `supabase migration new logistics_workspace`를 실행하여 생성한다. main 병합, hosted migration 적용, QA alias 변경, Production 배포는 별도 승인. 스키마 적용 전 메뉴는 데이터 준비 전 상태를 표시하고 로컬 가짜 저장으로 대체하지 않는다.
