# 태장 월말 급여대장과 직원 명세서 교부 v1

2026-11-25 업무 요구사항 · 2026-11-26 사용자 승인으로 구현 착수.

## 운영 흐름

급여월을 고르면 ERP 안에서 ① 초안, ② 회신 대조, ③ 명세서 교부를 차례로 처리합니다. 지급일은 매월 말일입니다. 기존 출근부를 근태 자료로 사용합니다.

| 단계 | 운영총괄이 하는 일 | ERP에 남는 결과 |
| --- | --- | --- |
| ① 급여대장 초안 | 25~28일경 당월 출근부를 확인하고 초안 Excel을 내려받아 세무사무실에 보냅니다. | 보낸 초안의 버전, 자료 기준일, 직원별 실적·예정 항목 |
| ② 세무 회신 대조 | 회신 Excel을 올리고, 출근부 정정과 급여 변경 사항이 반영된 ERP 검토본과 대조합니다. 차이가 있으면 근거를 확인하고 필요한 경우 수정 회신을 받습니다. | 세무 회신본, ERP 검토본, 행별 대조 결과와 운영총괄 확인 이력 |
| ③ 직원 명세서 교부 | 운영총괄이 회신본을 확인·확정하면 ERP가 해당 버전의 직원용 명세서를 생성합니다. 운영팀장이 조회·다운로드하고 인쇄하여 개인별로 교부합니다. | 확정 명세서, 버전, 인쇄 교부 기록 |

## ① 월중 초안

- 기준일까지는 ERP 출근부의 기록과 확인된 근태를 가져옵니다. 기준일 이후 근무일은 근무 일정과 이미 확인된 연차를 사용해 예정으로 구분합니다. 기록 누락과 예정은 구별하고, 휴무일에는 예정 근무를 채우지 않습니다.
- 월 전체의 출근부 확정을 초안 생성 조건에서 해제합니다. 초안 화면과 Excel에 근태 기준일과 월말까지의 예정분을 표시합니다. 기준일 이전 근태 누락은 확인 항목으로 표시합니다.
- 주휴 산정 등 초안 작성에 실제로 사용한 전월 말 날짜가 있으면 계산 근거에 포함합니다. 10월 초안에는 9월 28~30일이 포함돼 있습니다.
- 기존 급여 산출값이 있으면 지급·공제 합계를 가져옵니다. 운영총괄이 이번 월의 금액과 산출 근거를 확인하고, 가져올 값이 없는 항목은 직접 입력합니다.
- 세무사무실에 보낸 Excel의 내용은 고정합니다. 다시 보낼 때는 버전을 올려 이전 파일을 추적할 수 있게 합니다.

## ② ERP 검토본과 세무 회신

- ERP 검토본은 ①의 발송 버전과 이후 근태·급여 변경을 기준으로 만들어 회신본과 독립적으로 대조할 수 있게 합니다. 두 자료는 대조 화면에서 같은 직원의 좌우에 표시합니다.
- 최초 연결 시 세무 사번과 ERP 직원 ID를 확인합니다. 월별 대조는 저장된 연결을 사용합니다. 중복 사번, 연결 실패, 대상월·지급일 오류를 확인 항목으로 표시합니다.
- 직원 목록과 직원별 지급합계·공제합계·실지급액을 비교합니다. 지급·공제 세부 항목은 초안과 회신의 항목 구성이 다를 수 있으므로 합의한 항목 대응 기준에 맞춰 비교합니다. 확인이 필요한 행을 먼저 표시하고, 월 합계는 각 행에서 다시 합산합니다.
- 근태 정정 누락, 금액 차이, 직원 연결 오류, 항목 합계 오류를 해소한 후 운영총괄이 회신본을 확정합니다. 세무사무실에서 확정한 공제 등으로 차이가 생기면 담당자가 사유와 적용 값을 확인해 ERP 검토본에 반영한 뒤 다시 대조합니다.
- 확정 이후 발생한 근태·금액 정정은 변경 사유와 새 회신·명세서 버전을 연결합니다. 기존에 교부한 명세서와 재교부 이력을 보존합니다.

## ③ 직원 명세서와 역할

| 역할 | 조회·실행 범위 |
| --- | --- |
| 운영총괄 | 초안 작성·Excel 다운로드, 회신 등록·검토·확정, 직원 명세서 생성·조회·출력 |
| 운영팀장 | 확정된 직원 명세서의 월별 목록·개인 원본 조회, 다운로드·인쇄 및 교부 기록 |
| 직원 | 1차는 인쇄 교부. 직원앱 도입 이후 기존 로그인으로 본인의 발행 명세서만 열람·다운로드 |

- 직원급만 명세서를 생성합니다. 대표·임원은 명세서 대상에서 제외합니다. 해당 월에 지급받은 퇴사 직원은 직원 교부 대상에 포함합니다. 세무 대장과 직원 명세서의 인원 차이는 사유를 표시합니다.
- 회신본의 확정 직원별 금액으로 기존 A4 서식을 채웁니다. 누락된 산출 근거는 운영총괄이 확인하여 추가합니다. 직원당 한 장씩 미리보기와 PDF 출력을 지원합니다.
- 운영팀장용 조회는 확정된 명세서와 교부에 필요한 최소 필드만 반환하는 서버 권한을 사용합니다. 기존 초안·대장·계산 권한과 별도로 검사합니다. 목록·상세 조회와 파일 다운로드에 같은 서버 검사를 적용합니다.
- PDF는 브라우저 인쇄 화면에서 PDF로 저장합니다. 인쇄 교부는 실제 전달 후 별도 버튼으로 기록합니다.
- 앱 교부는 인쇄 흐름을 표준화한 뒤 추가합니다. 동일한 확정 버전을 직원 계정에 연결하고, 직원앱에서 본인 여부를 서버에서 검증합니다.

## 재사용 및 변경 지점

- 기존 ERP의 출근부 조회, 직원 ID, 급여대장 XLSX 출력과 명세서 서식을 우선 재사용합니다.
- [기존 근태 확정 흐름](ATTENDANCE_TO_PAYROLL_DRAFT_FLOW_V1.md)은 월 전체 확정 근태를 기준으로 한 내부 산출 흐름입니다. 신규 월중 제출 초안에 적용할 근태 기준일과 예정 구분을 별도로 정의합니다.
- [기존 급여 접근 결정](PAYROLL_DRAFT_HANDOFF_CONTRACT_V1.md)은 운영팀장의 급여 관리 접근을 철회했습니다. 신규 운영팀장 접근은 ③의 확정 명세서 조회·다운로드·교부 기록으로 한정하는 설계입니다.
- 운영총괄은 ERP의 기존 세션으로 월별 마감을 진행하고, 운영팀장은 같은 ERP에서 교부 화면을 엽니다. 기존 급여 자료와 감사 이력은 보존합니다.

## 수용 기준

1. 28일에 말일까지의 근태 기록이 없어도 예정 근무, 휴무, 승인 연차를 구분한 초안 Excel을 받을 수 있습니다.
2. 발송 후 10월 27일 같은 결근→연차 정정이 나오면 발송본을 유지하면서 ERP 검토본과 세무 회신에 어떻게 반영됐는지 확인할 수 있습니다.
3. 10월 샘플에서는 대조 화면이 22명 일치, 1명 금액 차이와 대표 1명 교부 제외를 구분합니다. 금액 차이가 해소되면 직원급만 명세서를 생성합니다.
4. 같은 확정 회신을 다시 열거나 작업을 재시도해도 명세서가 중복 생성되지 않습니다.
5. 운영팀장은 ③의 확정 PDF를 열 수 있고, 동일 계정으로 ①·② 화면 또는 해당 서버 API에 직접 접근하면 거절됩니다.
6. 직원앱 단계에서는 두 직원 계정으로 본인 열람·다운로드와 타인 명세서 접근 거절을 검증합니다.
