# 월별 거래처 문서 관리 V1

상태: 사용자 지시 범위 확정 / 원본 업무 자료 확인 대기
확정일: 2026-10-01
적용 기준: PROJECT_CHARTER.md, PLATFORM_CONSTITUTION.md, PLANNING_RECORD_SYSTEM.md, UNIFIED_CAPABILITY_SIDEBAR_V1.md

## 목적과 승인 범위

운영총괄이 매월 4개 거래처에 제출하는 공문·견적서·결과보고서를 기존 태장 플랫폼에서 생성한다. 기존 Claude 프로그램의 계산·문구·A4 양식을 그대로 이식해 반복 입력과 출력 오류를 줄인다. 태장 Domain으로 구현하고 Auth/capability/공통 UI는 기존 Core를 재사용한다.

사용자가 승인한 범위는 감사, 설계, 구현, 테스트, Draft PR, Deploy Preview, PC/mobile 자체 검수, 오류 수정과 재검수다. main 병합, Ready for review, Production DB 변경·배포, 실제 문서 발송은 제외한다. migration 파일 작성은 허용하되 remote DB 적용은 별도 안전 절차가 확인될 때만 수행한다.

## 확정 업무 계약

- 운영총괄만 사용한다. CEO, super_admin 단독, 운영팀장, 일반직원 및 lower-role simulation은 접근 불가다.
- 메뉴, 직접 route, 읽기/쓰기 API와 DB, 확정/해제, 문서 생성/다운로드를 모두 보호한다.
- 월 선택 → 공통 정보 → 추가 프로그램 → 회사별 카드 → 계산/경고 → 저장 → 확정 → PDF 순서로 한 화면에서 처리한다.
- 공통 입력은 기준월, 작성일, 수행일, 장소, 월별 계산 기준값, 안전교육 방식(야외/실내 영상)이다. 실제 출력 표현은 원본 기준이다.
- 회사별 회사명, 지분율, 계약 상한, 적용 인원, 지급기한, 문서 순번, 개별 안내 문구를 관리한다. 범한 적용 인원 6명은 사용자 확인값이다. 다른 계약값은 추정하지 않는다.
- 적용 인원 미입력 시 계산상 최대 인원과 계약 상한 중 작은 값을 적용한다. 정확한 최대 인원·총 산입·금액 계산 및 반올림은 원본 코드 확인 후 이식한다.
- 순수 deterministic 계산 모듈 하나를 화면과 출력이 공유한다. AI API와 Claude 실행 의존은 없다.
- 상한/최대 인원 초과는 텍스트와 빨간 경고로 표시하며 잘못된 확정/다운로드를 막는다. 실무 예외는 원본에서 확인한다.
- 추가 프로그램 이름·설명·사용 여부에 따라 공문 2항이 분기한다. 정확한 문구는 원본에서 가져온다.
- 회사별 안내 문구가 비어 있으면 출력하지 않는다. 기본값과 월별 override의 필요 여부는 원본 확인 후 결정한다.
- DB에 월 설정과 회사별 계약 snapshot, 추가 프로그램, 작성 상태, actor/time을 저장한다. localStorage는 authoritative 저장소로 사용하지 않는다.
- 기본 설정 변경으로 과거 월이 바뀌지 않는다. 입력 snapshot과 calculation/template version으로 과거 문서를 재현한다.
- 지난달 복사는 회사 계약 설정과 반복 장소/설정만 유지한다. 작성일·수행일·월 표기·월별 문서번호·확정 상태를 초기화/새 월 기준 갱신하고 일회성 프로그램은 제거한다.
- 상태는 작성중/확정이다. 확정 월 수정은 서버에서 차단하고 명시적인 확정 해제 후 수정한다. 승인자·결재라인은 추가하지 않는다.
- 회사별 PDF는 공문 → 견적서 → 결과보고서 3페이지, 전체 PDF는 회사 순서대로 12페이지다. 각 문서 A4 1페이지와 기존 여백을 유지한다.
- 파일명은 YYYY-MM_회사명_공문견적결과보고서.pdf 또는 YYYY-MM_4사_공문견적결과보고서.pdf다.
- 직인 날인 → 스캔 → 거래처 전달 흐름을 유지한다. 제출 양식을 임의로 디자인 변경하지 않는다.
- 7·8월 일회성 소급 로직과 직원/민감정보 연계는 제외한다.

## 감사에 따른 구현 방향

신규 capability는 monthly_client_documents.manage로 계획한다. 기존 operational registry와 operations_manager_auto_grant를 재사용하고 다른 역할의 grant는 만들지 않는다. effective capability와 서버 private_actor_can 판정을 사용한다. 실제 migration은 아직 작성하지 않았다.

메뉴 후보는 거래처 문서 관리이며 기존 업무 운영 section에 추가한다. dashboard-shell의 masterMenuItems, platform-navigation-registry, role-navigation-priority, capability-ui-gates의 기존 계약을 함께 반영하고 별도 사이드바 소유자를 만들지 않는다.

월 snapshot을 aggregate로 읽고 서버 RPC에서 저장/확정/해제를 원자적으로 수행하는 방향이다. 낙관적 revision 검사로 오래된 화면의 저장과 확정 경쟁을 막는다. 테이블 세부 컬럼과 계산 snapshot 계약은 원본 입력/계산 필드 확인 후 확정한다. 기존 직원·급여 테이블에 문서 데이터를 섞지 않는다.

회사 기본 설정, 월 세트, 회사별 월 snapshot, 프로그램을 분리하는 최소 구조를 검토한다. 미래 멀티테넌트 시스템을 선행 구현하지 않고 기존 조직 경계 패턴에 맞춘다.

기존 XLSX exporter와 브라우저 인쇄는 참고 가능하지만 자동 PDF 생성 엔진은 조사 범위에서 확인되지 않았다. 브라우저 print만으로 지정 파일명 PDF 자동 다운로드를 완료 처리하지 않는다. 원본 양식 확인 후 경량 PDF 방법의 한국어 폰트·A4 페이지 분리·라이선스·bundle 비용을 비교한다. 원본 확인 전 새 dependency는 도입하지 않는다.

## 구현에 필요한 원본 자료

1. 현재 검증 완료 Claude 프로그램 소스 또는 접근 가능한 Artifact URL.
2. 4사 기본 계약값, 지분율 단위, 지급기한과 문서번호 규칙.
3. 총 산입·최대 인원·공급가액·부가세 등 계산과 절사/반올림 규칙.
4. 기존 공문·견적서·결과보고서 양식과 정확한 문구(추가 프로그램/개별 안내 포함).
5. 2026-09 입력값과 4사 인원·금액·문서번호 golden 결과. 공개 저장소에 계약 원문이나 비공개 실자료를 커밋하지 않고 허용된 익명 fixture만 사용한다.

2026-10-01 조사에서 저장소와 관련 GitHub Issue 검색으로 위 자료를 찾지 못했다. 회사 이름과 범한 6명 외의 값을 추정해 구현하거나 임의 golden fixture를 만들지 않는다.
