## 확정 흐름과 범위

- 직원 목록 → 직원 선택 → 한 명의 읽기 전용 인사카드 → 기본정보 수정 → 저장/취소 → 재조회.
- PC는 한 직원당 한 행, 모바일은 가로스크롤 없이 압축 리스트. 사진/이니셜, 직원번호, 이름, 부서, 직책, 재직, 앱, 근태, 사진, 점검 상태 표시.
- 이름/직원번호 검색과 재직(전체/재직/퇴직), 앱(전체/연결/미연결/확인 필요), 업무용 사진(전체/있음/없음) 필터. 뒤로가기에서 검색·필터와 선택 행 초점 복원.
- 휴직은 재직 필터에 포함하되 휴직으로 표시한다. 앱 연결 여부는 `linked_profile`의 존재, 활성 여부는 `account_status`로 구분한다. 비활성 연결도 앱 연결 필터에 포함한다.
- 인사카드 순서는 기본 인사정보 → 앱 계정 → 업무용/증명사진 → 민감정보/보험 → 기록/점검. 직원번호는 읽기 전용.
- 운영총괄의 직접 수정과 팀장의 기존 승인 요청을 유지한다. 보호 직원 제한, 증명사진 조회 제한, 민감정보 capability와 보험 RPC 경계 유지.
- 신규 등록은 상단의 별도 액션/화면. 기존 승인 요청과 연락처 요청의 검토 기능도 유지한다.
- 주민번호 일괄등록은 권한 있는 직원 목록의 `일괄 작업` 아래 접힌 도구로 보존한다. 개인 인사카드에는 개인 작업만 둔다.
- 2026-10-14 Issue #453 사용자 추가 확정: 첫 진입은 재직(휴직 포함)이 기본. 전체에서는 재직/휴직을 위에, 퇴직자를 구분선과 소제목 아래 하단에 배치한다. 검색·앱·사진 필터와 목록 복귀 상태는 유지한다. 이전 전체 기본값 및 상세 내부 일괄등록 위치를 변경한다.

## 연결 점검과 안전

- 현재 context 조회 범위에서 이름과 입사일이 모두 같고 연결/미연결 직원이 혼재할 때 해당 그룹에 `연결 확인 필요` 표시. 같은 이름만으로는 판단하지 않는다.
- 연결된 Profile 상태가 미확인이거나 활성/비활성 이외 상태이면 확인 경고를 표시한다. 경고는 확정 중복/자동 매칭을 뜻하지 않는다.
- 추가 DB 조회, 자동 병합/삭제/재연결, 직원번호/실계정 변경 없음. #442/PR #443 가입 승인 로직은 수정하지 않는다.
- 앱 이메일은 기존 context에 허용된 값만 사용한다. 팀장은 증명사진 상태를 조회 불가로 표시하며 등록 안 됨으로 단정하지 않는다.
- 사진은 Storage 업로드 → 기존 사진 RPC(팀장 증명사진은 변경 요청) → context 재조회 → 경로/요청 일치 확인 후에만 완료 표시. 실패 시 성공 표시 금지, 입력 유지. 실제 직원 사진 사용 금지.
- 새 backend/API/라이브러리 없음. 기본 인사정보·사진·민감정보·보험 저장 실패 경계 분리.
