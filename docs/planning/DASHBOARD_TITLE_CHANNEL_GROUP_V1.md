## 화면 위계
- 좌측 사이드바 브랜드 `태장 / 업무플랫폼` 유지
- 상단에는 현재 역할명만 표시
- 상단의 작은 `태장 업무플랫폼` 제거
- 역할 대시보드 본문 제목은 공통 `대시보드`
- 역할별 설명 문구는 유지

## 운영총괄 화면 원칙
운영총괄은 상시 조회보다 지금 승인·결재·처리해야 할 항목을 먼저 본다.

대시보드 우선 항목:
1. 가입 승인
2. 직원관리 요청
3. 중요 홍보 승인
4. 홈페이지 수정 승인

출근부·일정·공지는 필요할 때 메뉴에서 조회할 수 있게 유지하되 운영총괄 대시보드 핵심 카드에서는 제외한다.

운영총괄 사이드바에서 출근부는 상시 핵심업무가 아니므로 `조회·도구` 영역의 후순위에 둔다.

## 가입 신청 안내·거절
가입 신청자에게 특정 직책명을 노출하지 않는다.

승인 대기 안내 문구:
> 관리자 확인 후 승인됩니다.

운영총괄은 모든 신청을 승인할 의무가 없으며 잘못된 신청·비직원·중복 신청 등을 거절할 수 있다.

가입 거절은 Auth 사용자를 물리 삭제하는 방식이 아니라 다음처럼 처리한다.
- `profiles.account_status`: `pending` → `deleted`
- 승인 대기 목록에서 즉시 제외
- `account_status_history`에 상태 변경 기록
- 감사로그에 거절 기록
- 업무 역할은 부여하지 않음

기존 Auth/RLS 권한 의미와 활성 계정 판정 방식은 변경하지 않는다.

## 운영총괄 삭제 권한
운영총괄은 테스트 자료·잘못 등록된 자료를 직접 정리할 수 있어야 한다.

사용자 화면에서는 모두 `삭제`로 표현한다. 다만 데이터베이스에서는 관계 무결성·감사 추적·오삭제 복구를 위해 복구 가능한 삭제를 사용한다.

### 직원 삭제
- 운영총괄만 가능
- 대표이사·운영총괄·시스템관리자 등 보호 계정과 연결된 직원은 삭제 불가
- 직원 레코드는 물리 삭제하지 않고 `archived_at` 등 보관 메타데이터를 기록
- 일반 직원관리 목록과 신규 가입 연결 후보에서는 즉시 제외
- 연결된 업무플랫폼 계정이 있으면 `account_status = deleted`로 접근 차단
- 현재 계정-직원 연결은 종료 처리
- 직원번호, 사진, 변경요청, 계정 상태이력, 감사로그는 보존

### 일정·공지·안내 삭제
- 운영총괄만 삭제 가능
- 상태를 `inactive`로 전환
- 일반 직원 화면과 일반 관리 목록에서 제외
- 원본 레코드와 감사로그는 보존
- 공지 확인이력 등 연관 이력은 삭제하지 않음

### 글 삭제
- 운영총괄은 초안·검토중·수정필요·승인완료·발행예정·공개·숨김 글을 직접 삭제 가능
- 삭제 시 `promotion_contents.lifecycle = archived`
- 대기 중 검토 요청은 `withdrawn`, 발행 대기는 `cancelled` 처리
- 홈페이지/일반 글 관리 목록에서는 제외
- 원문 revision, 검토·승인 이력, 감사로그는 보존
- 운영팀장은 기존처럼 직접 삭제하지 않고 삭제 요청 흐름을 사용

모든 삭제는 사유 입력과 확인 절차를 거친다.

## 사이드바 정보 구조
긴 메뉴를 한 줄 목록처럼 보이지 않게 역할에 맞춰 얇은 구분선과 작은 섹션명을 표시한다.

기본 구분:
- 승인·관리
- 업무 운영
- 조회·도구
- 공식 채널
- 점검중

역할에 없는 구분은 표시하지 않는다. 대시보드는 최상단에 별도로 유지한다.

## 공식 채널
홍보직원·운영팀장·운영총괄에게 별도 `공식 채널` 그룹을 표시한다.

1. 홈페이지
2. 공식 블로그
3. 공식 유튜브

업무 메뉴와 시각적으로 분리하고 모든 링크는 새 탭으로 연다.

## 권한·안전 범위
- 삭제 권한은 운영총괄에게만 추가하고 다른 역할의 권한은 확대하지 않는다.
- 직원의 기존 식별자·직원번호·인사 기본 구조는 유지하고 보관용 메타데이터만 추가한다.
- GPS 출퇴근 서버 로직을 변경하지 않는다.
- 홍보 승인·발행의 정상 업무 흐름은 변경하지 않는다.
- 삭제는 물리 파괴보다 복구 가능한 상태 전환을 우선한다.
