# 태장 직원앱 설정 패치노트 V1

상태: 사용자 요청에 따른 구현 기준 확정 (2026-10-31 KST).

## 목적과 사용자 흐름

- 요청: 업무수첩 앱처럼 태장출근앱에도 변경 기록이 자동 반영되는 패치노트 메뉴를 설정에 추가한다.
- 모든 앱 사용자가 `설정 → 패치노트`에서 날짜·제목·요약·변경 항목을 최신순으로 읽고 설정으로 돌아간다.
- 설치 버전·빌드 번호를 함께 표시한다. 기록일은 코드 변경 기록일이며 Play 게시일을 뜻하지 않는다.
- 업무수첩 `cetin072/worklog-voice-pwa`의 `mobile/src/features/settings/patch-notes.ts` 정적 데이터 방식과 유지 규칙을 참고해 태장에 독립 구현한다. 외부 코드·의존성을 가져오지 않는다.

## 자동 반영의 의미와 기록 책임

- 원본은 `mobile/src/features/settings/patch-notes.ts` 한 곳이다. 화면은 이 배열을 직접 읽으므로 별도의 화면 수정·입력·동기화 없이 앱 빌드/업데이트에 함께 반영된다.
- 사용자에게 보이는 모바일 기능·화면·동작 변경을 구현하는 개발 작업은 같은 PR에서 기록을 추가한다. 기존 기록을 보존하고 최신 항목을 위에 둔다. 개발자가 사용자용 설명을 작성하며 커밋 메시지나 내부 오류 로그를 자동 공개하지 않는다.
- 테스트·CI·문서만의 변경, 사용자 동작이 그대로인 내부 정리는 기록하지 않는다.
- 기록은 해당 코드를 포함한 앱 빌드에만 포함된다. QA 빌드에도 같은 소스의 기록을 표시하되, 미구현·다음 계획·운영 게시 완료 주장은 넣지 않는다. 구버전 설치 앱에 새 기록이 원격 전달되지는 않는다.
- 앱 실행 중 외부 패치노트 API 요청·새 로컬 저장·DB·Auth 변경은 필요 없다. 오프라인에서도 읽고, 로그인·연결 상태 때문에 이 화면이 비워지지 않는다.
- 기존 업데이트 후 1회 변경 안내와 Play 업데이트/점검 정책은 그대로 유지한다. 버전 번호 증가는 다음 승인된 앱 릴리스에서 처리한다.

## 검수와 범위

- 설정 진입·설정 복귀, 날짜 역순·고유 ID·빈 문구 방지, 현재 설치 버전과 빌드 표시를 검사한다.
- 네트워크·로그인·Storage 없이 실제 화면 컴포넌트를 렌더링해 모든 기록이 나오는지 확인한다.
- 작은 화면·큰 글자에서도 스크롤과 본문 줄바꿈을 허용한다. 새 권한·SDK를 추가하지 않는다.
- 현재 포함 기록: 이번 패치노트 메뉴, main #556의 홈 카드 정리, 0.1.6 후보 문서에 근거한 공지 카드 개선. Play 게시 여부를 이 문서에서 추정하지 않는다.
- 자동 검사·typecheck 후 Draft PR로 공유한다. 실기기 설치·업데이트·TalkBack 검수 및 새 앱 배포는 미확인 단계로 구분한다.
