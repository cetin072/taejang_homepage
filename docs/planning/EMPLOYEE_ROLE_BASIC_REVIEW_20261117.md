# 직원 기본정보의 직책·시스템 역할 확인

## 승인된 목적과 범위
직원 관리의 기존 색상·글자·간격을 유지하면서 기본정보에서 직책과 실제 접속 역할의 차이를 알아볼 수 있게 한다. 권한 있는 운영총괄이 추천 역할을 확인하고 소속·직책과 함께 저장하는 실행본을 검증한다. 사용자 프리뷰 요청에 따른 개발이며 main 병합, 운영 DB 적용, 실제 직원 역할 변경, Production 배포는 이번 작업에 포함하지 않는다.

## 단일 흐름
기본정보 → 실제 역할/불일치 조회 → 기존 수정 폼 → 직책 선택 → 추천 안내 → 명시 체크 → 변경 요약 확인 → 단일 원자 RPC → 직원정보 새로 읽기.

- 실제 역할은 단일 직원용 서버 조회이며 직책 문자열에서 접속 권한을 추론하지 않는다.
- 직책만 수정한 경우 역할은 자동 변경되지 않는다. 기본 선택은 체크 해제다.
- 기존 겸직·임시 역할을 모두 보존하고 안전한 직책 기본 역할만 추가한다. 이전 역할 회수가 필요한 경우 기존 역할 관리 도구에서 별도로 검토한다.
- 운영총괄 등 재위임 권한이 생길 수 있는 직책/기술관리자 역할은 자동 추천 대상이 아니다.
- 직원 관리 메뉴 위임은 계정 권한 위임이 아니다. 기존 employee.update, account.organization_manage, account.operational_roles_manage 및 실제 운영총괄 정책을 서버에서 확인한다.
- 직원/계정 연결/역할/프로필 최신성 충돌은 거부한다. 기존 core·조직·역할 API를 하나의 트랜잭션으로 호출하고 하위 API 실패는 전부 롤백한다.
- 일반 편집자에게는 역할 변경을 운영총괄에게 확인하라는 안내만 표시한다. 자동 요청 티켓 전송은 구현하지 않는다.

## 검증과 남은 게이트
- UI 합성 테스트: PC 1440 / 모바일 390 / 좁은 화면 320, 확인 취소, 실패 입력 보존, 중복 클릭, 재위임 제외, 권한 없는 편집자. 실제 계정 데이터 사용 없음.
- pgTAP: 권한 거부, 겸직 유지, 추가-only, stale snapshot, 중간 실패 rollback, 반복 저장, private RPC 권한.
- 로컬 브라우저는 Chromium socket 권한 제한으로 실행되지 않아 CI 브라우저 결과 필요. 정적 테스트는 실제 브라우저/DB 성공을 뜻하지 않는다.
- 새 migration은 아직 어떤 hosted DB에도 적용하지 않았다. Staging 계약 확인과 fixed qa-preview 점유 조정/HEAD/배포 환경 검증 완료 전 사용자 수용 검수를 요청하지 않는다.
- 현재 fixed QA는 main과 별도 홈페이지 변경을 가지고 있어 임의 덮어쓰지 않는다.

## 안전한 디자인 미리보기 대안
`app/employee-role-demo.html`은 동일 JS/CSS를 사용하는 가상 직원 전용 화면이다. connect-src none CSP 및 fetch 거부, 로그인 저장소 미사용, allowlist mock RPC로 데이터 API/실제 계정과 분리한다. 변경은 메모리에만 반영되고 새로고침 시 초기화된다. 개발 Deploy Preview에서만 자동 실행하며 운영 hostname에서는 열지 않는다. 이 페이지는 레이아웃/상호작용 설명용이며 고정 QA의 실제 로그인·저장 수용검수를 대신하지 않는다.
