# 태장 업무플랫폼 통합 사이드바·권한 원칙 V1

상태: **확정**
확정일: 2026-09-21
관련 Issue: #320

## 1. 핵심 원칙

태장 업무플랫폼의 데스크톱 사이드바는 직책별로 따로 만들지 않는다.

- 사이드바 정의는 **하나**만 둔다.
- 전체 메뉴 순서와 구역은 **운영총괄 기준 마스터 사이드바**를 기준으로 한다.
- 대표이사, 운영팀장, 부서팀장, 현장책임자, 홍보직원, 시스템관리자 등 다른 데스크톱 역할도 같은 메뉴 구조와 순서를 사용한다.
- 사용자에게 실제로 보이는 메뉴는 그 사용자의 **capability**에 따라 숨기거나 표시한다.
- 직책이 내려갈수록 메뉴 정의를 새로 만드는 것이 아니라 capability가 줄어들어 자연스럽게 표시 항목이 줄어든다.
- 화면에서 메뉴를 숨기는 것은 보안이 아니다. RPC/RLS/서버 capability 판정이 항상 최종 권한이다.
- 일반 근로자의 단순 모바일/직원 홈은 복잡한 데스크톱 사이드바의 예외로 유지한다.

## 2. 운영총괄 기준 마스터 메뉴

기본 순서는 다음 한 개의 registry로 관리한다.

1. 대시보드
2. 직원·계정
3. 홍보
4. 홈페이지
5. 업무 운영
6. 공지·안내
7. 근태·급여
8. 지원사업 등 capability 기반 확장 메뉴
9. 공개 홈페이지·공식 채널

기능 모듈이 추가 메뉴를 제공할 수는 있지만, 역할별 메뉴 복제본을 만들지 않는다. 기능 모듈은 자신의 메뉴 슬롯과 필요한 capability만 등록한다.

## 3. 권한 모델

### 운영총괄

운영총괄은 모든 **operational capability**의 기준 역할이다.

- 운영 기능은 운영총괄에게 자동 부여한다.
- 하위 역할은 필요한 operational capability만 갖는다.
- 시스템 기술 비상권한 등 technical capability는 별도의 최고관리자 역할로 유지한다.

### 김형철

김형철의 조직·시스템 기준은 다음과 같다.

- 직위: **전무이사**
- 역할: **운영총괄**
- 겸임: **시스템 최고관리자**
- 태장 업무플랫폼 전체 설계·운영 담당
- 운영총괄 operational superset + 최고관리자 technical 권한을 합쳐 **활성 기능 전체를 사용할 수 있는 최고 권한 계정**으로 운용한다.
- 직원 DB의 김형철 Employee와 로그인 계정을 연결한다.
- 급여는 기존 확정 기준대로 비근태 월급제 임원으로 유지한다.

## 4. 구현 규칙

- dashboard-shell은 한 개의 master menu registry에서 기본 메뉴를 만든다.
- role-navigation-priority는 한 개의 master order/section contract만 유지한다.
- capability-ui-gates는 메뉴 노드의 capability를 읽고 표시 여부를 결정한다.
- 후속 모듈은 role 조건으로 별도 사이드바를 만들지 말고 capability 조건으로 메뉴 슬롯을 등록한다.
- 직책은 대시보드 설명, 업무 문구, 화면 기본 진입점처럼 UX 문맥에는 사용할 수 있다.
- 데이터 열람/수정 범위는 capability + 서버 권한으로 결정한다.

## 5. 검수 기준

- 데스크톱 역할별로 별도의 메뉴 배열을 유지하지 않는다.
- 모든 데스크톱 역할에서 같은 마스터 순서가 유지된다.
- 권한이 없는 메뉴는 숨겨지며 직접 URL/RPC 접근도 서버에서 차단된다.
- 운영총괄은 모든 operational capability 메뉴를 볼 수 있다.
- 김형철은 operations_manager + super_admin 결합으로 활성 capability 전체를 가진다.
- 김형철 로그인 계정은 김형철 Employee / 전무이사와 연결된다.
- 역할 시뮬레이션에서도 메뉴 구조는 같고 capability에 따른 표시만 달라진다.
- 일반 근로자의 단순 모바일 화면은 회귀하지 않는다.
