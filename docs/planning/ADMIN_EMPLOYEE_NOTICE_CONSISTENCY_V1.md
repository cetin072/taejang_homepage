# 직원 정렬·상세 사진·공지 저장 확인 개선

상태: 확정 — 2026-10-19 사용자 실행 지시. 기준: `ADMIN_UI_READABILITY_V1.md`, `ISSUE_451_EMPLOYEE_LIST_PROFILE_CARD_V1.md`, `ROLE_PERMISSION_MATRIX_V1.md`, 플랫폼 헌법 §4.

## 범위

- 운영총괄을 공통 UI 기준으로 삼고 동일 직원 views/controller·공지 작성기·목록을 재사용한다. 권한·승인선·민감정보·급여 경계는 서버 계약을 유지한다.
- 직원 목록 기본 정렬: 기존 positions의 직책 높은 순, 일반 근로자(code=general_worker)는 마지막, 같은 직책은 불변 직원번호 오름차순. 직원번호 양방향/이름/부서/입사일 최신순 선택과 검색·필터·상세 복귀 상태를 유지한다.
- 재직·휴직 기본, 전체에서는 퇴직 그룹을 하단에 둔다. 미지정/조회 기준에 없는 ID/명칭 불일치는 확인 필요 그룹으로 분리한다. 이름으로 직책을 추정하지 않는다.
- 현재 RPC는 positions를 `general_worker` 우선 후 DB `sort_order` 순으로 제공하지만 숫자 필드를 생략한다(`20261016100000_lead_staff_roster_resident_number.sql`). 기존 정렬된 응답 순서를 재사용하고 general_worker만 마지막으로 옮긴다. 숫자가 제공되면 직접 사용한다. 새 조회·스키마·migration 없음.
- 상세 상단 업무용 사진 PC 120px/모바일 100px. 목록 썸네일 40px와 사진 관리 UI는 유지한다. 기존 signed URL·401 갱신·실패 대체·등록/변경/재조회 계약 유지.
- 업무용 사진은 목록/상단 식별용, 증명사진은 공식 인사용이며 목록에서 사용하지 않는다. 사진 삭제·권한 변경 없음. 증명사진 조회와 서버 직접 등록은 운영총괄 중심, 팀장의 기존 요청 경로는 보존한다.
- 코드 대조에서 확인한 표시 오류: 미등록 증명사진의 undefined 경로가 avatar 기본 인자로 업무용 사진을 대신 사용했다. 각 호출의 경로를 명시하여 미등록 증명사진은 대체 표시만 보여준다. 사진 데이터 변경 없음.
- 공지 저장/게시/상신 성공 후 관리 목록을 보이게 하고 저장한 공지를 표시·바로 찾기 제공. 저장 ID·원고·미리보기 유지. 실패/부분 성공/조회 누락은 구분하고 재게시/중복 생성하지 않는다.
- 공지 상태는 비공개 초안/운영총괄 검토 대기/예약 게시/게시 중/게시 종료/취소·사용 중지로 구분한다. 기존 routine/review 서버 승인 경계 유지.
- 기타 공개글 수정 요청은 사용자가 지정한 안내 문구로 교체한다. URL·수정 내용·사유와 요청 RPC는 그대로 유지한다.

## 기존 화면 비교·재사용

최신 main #487에서 적용한 Tabler section/action 패턴과 GOV.UK summary list는 직원·가입 승인·홍보·홈페이지 화면에서 이미 공유된다. `ADMIN_UI_PATTERN_REUSE.md`의 CSS 소유권을 유지하고 정상 화면을 재작성하지 않는다. 직원 크기는 employee-management.css, 정렬은 기존 views, 공지 전환은 notice-admin.js가 각각 소유한다. 신규 프레임워크·의존성 없음.

## 검증과 경계

합성 직원/사진·mock RPC로 PC/모바일 정렬·필터·상세 복귀·사진 크기/실패 대체, 공지 저장→목록→동일 ID 수정 및 실패 입력 보존을 검사하고 before/after 캡처를 만든다. 운영총괄·운영팀장·홍보직원 회귀와 기존 서버 Auth/RLS 검증을 사용한다. 실제 직원·급여·공지·계정·원본 데이터는 변경하지 않는다. Draft PR/고정 QA의 HEAD·실제 배포·연결 환경을 대조하고 미확인 항목은 보고한다. main/Production은 별도 사용자 승인.
