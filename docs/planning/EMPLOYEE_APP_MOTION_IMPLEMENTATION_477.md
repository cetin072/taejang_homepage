## 기술과 안전

- `employee-app.html`, 전용 CSS, 전용 로컬 JS 한 개. 전역 site.js·직원앱·Auth/DB·배포 설정 무변경.
- SVG `d` 보간은 승인 V2.1 render 함수를 그대로 재사용. 카드 회전은 브라우저 Web Animations API. 외부 런타임/폰트/이미지 추가 없음.
- 모든 문장은 정적 DOM. Before/After는 각각 유효한 `dl/dt/dd`; 장식 SVG는 기존 aria-hidden 유지. 회전 중에도 양쪽 텍스트는 접근성 트리에 남으며, 원하면 정적 비교로 전환 가능.
- no-JS는 두 상태 비교. reduced-motion은 두 상태 비교 및 HERO 최종 프레임. 설정 변경·인쇄 시 즉시 정적, 해제 시 자동 재시작 없음.
- 카드 앞뒤는 grid의 같은 셀로 최대 높이를 확보, 처음 화면에 들어오기 전에 준비. 회전 중 레이아웃 높이를 바꾸지 않는다. 사용자가 정적 비교를 선택할 때만 읽기 배치 확장.
- 기존 테스트의 제거된 CSS 등장 효과 검사는 새 SVG/카드의 실제 타이밍·종료·키보드·양면 접근 검증으로 대체한다. 관련 없는 회귀를 삭제하지 않는다.

## 기존 hosted CI 진단

원래 작업 `38927385483 / 117063261825` 로그에서 첫 화면 `page.goto(...networkidle)` 30초 실패를 확인했다. 당시 로그에는 요청 trace가 없어 **과거에 어느 요청이 멈췄는지는 확정할 수 없다**.

같은 #478 Preview를 읽기 전용 Chrome으로 추적한 새 표본에서는 두 경로 모두 성공했다. 직원앱 페이지에도 Netlify `/.netlify/scripts/cdp` → `app.netlify.com/cdp` iframe → Segment/Bugsnag 요청이 들어온다. 외부 글꼴과 기존 공개 보강 API도 존재한다. 이는 networkidle이 앱과 무관한 툴바까지 대기한다는 근거이며, 과거 실패 원인 확정은 아니다.

보강: 문서 200 + 메인 프레임 제품 요청 완료 + CSS 실제 적용 + 글꼴 loaded + 뷰포트 이미지 decode 상태 + h1 표시 + header/main/footer 배치 안정 확인. 메인 프레임 선택적 공개 API의 오류는 기존 정적 fallback 계약대로 기록하되 핵심 리소스 실패는 허용하지 않는다. 모든 pending/실패/완료 요청을 CI artifact로 저장한다. Netlify 툴바를 차단하거나 운영 설정을 바꾸지 않는다.

별도 브라우저 fixture는 ‘툴바 iframe만 지연되면 networkidle 실패/제품 준비 성공’, ‘제품 CSS 지연이면 준비 검사 실패’를 검증한다. 새 exact-head hosted CI 결과와 함께 판단하며 green을 과거 원인 확정으로 확대하지 않는다. 재현 불능 원인 미확정은 운영 반영 차단 사유로 남긴다.
