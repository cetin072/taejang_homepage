# 태장 지원사업 레이더 — 적합도 규칙·Golden Set v1

Status: **검토 중**  
Parent: #161 / #165  
Purpose: `태장 적합도 100점`이 AI 기분에 따라 흔들리지 않도록 결정론적 규칙, AI 역할, 중대한 오판 기준, Golden Set 검수 방식을 정의한다.

---

## 1. 핵심 원칙

평가 순서:

> 사실 추출 → Hard Gate 판정 → A/B/C 참여경로 판정 → 6영역 점수 → AI 해석/확인질문 → 사람 검토

다음은 금지한다.

- 공고 원문을 읽고 LLM에게 `0~100점 하나만 매겨라`라고 맡기기
- 필수자격이 불명확한데 `신청 가능`으로 단정하기
- 높은 지원금 때문에 신청불가 사업을 고득점으로 올리기
- 현재 태장 사업과 `향후 해볼 수도 있는 사업`을 같은 강도로 평가하기
- 근거 없이 선정가능성을 숫자로 과장하기

---

## 2. 평가 출력

모든 평가에 최소 다음을 포함한다.

- `overall_score` 0~100
- 6개 세부점수
- `direct_eligibility`
- `joint_eligibility`
- `partner_eligibility`
- `recommended_application_mode`
- `recommendation`
- `recommendation_reason`
- `qualification_gaps`
- `questions_to_confirm`
- `taejang_possible_role`
- `next_action`
- `confidence`
- `evidence`

점수만 존재하는 평가는 유효한 최종 평가로 취급하지 않는다.

---

## 3. Hard Gate

Hard Gate는 `점수를 깎는 요소`와 `현재 직접신청을 막는 요소`를 구분한다.

### 3.1 직접신청 Hard Fail 후보

공고에 명확한 근거가 있고 다음이 태장과 불일치할 때 `direct_eligibility=ineligible` 후보:

- 신청주체가 개인만 가능
- 비영리법인만 가능하고 영리법인 공동/참여 규정 없음
- 특정 지역 소재만 가능하고 태장 사업장 두 곳 모두 해당하지 않음
- 필수 업종/등록이 명확히 요구되며 태장이 해당하지 않음
- 신청접수 마감 완료
- 특정 필수 인증이 접수일 기준 반드시 필요하고 태장이 보유하지 않음
- 이미 수혜 중인 사업과 명백한 중복지원 금지로 신청 불가

### 3.2 `conditional`로 남겨야 하는 경우

- 중소기업확인서처럼 현재 미보유지만 취득 가능성/기한 확인이 필요한 경우
- 특정 협약기관 또는 컨소시엄 구성으로 참여 가능할 수 있는 경우
- 사업장이 여러 곳이고 어느 사업장 기준인지 확인이 필요한 경우
- 공고문과 첨부문서 해석이 충돌하는 경우
- 접수 전 자격취득을 허용하는지 불명확한 경우

### 3.3 `verify`를 써야 하는 경우

- 공고 요약에는 대상이 있으나 첨부 원문이 없거나 불충분
- 기업규모 기준이 모호
- 농업회사법인/영리법인 포함 여부 불명확
- 공동신청/협력기관 규정 미확인
- 중복지원 제한이 추상적
- 지원금액/자부담이 원문에서 확인되지 않음

불확실성을 억지로 `eligible`로 바꾸지 않는다.

---

## 4. A/B/C 판정

각 경로를 독립적으로 평가한다.

### A. 직접신청

- `eligible`: 현재 태장이 주요 필수조건을 충족
- `conditional`: 부족 자격/사전조치가 해결되면 가능
- `ineligible`: 명확한 필수조건 불일치
- `verify`: 근거 부족

### B. 공동신청

공고에 컨소시엄, 공동수행, 참여기업, 협력기업, 수요기업 등의 구조가 있는지 본다.

### C. 협력기관 활용

태장이 주관기관이 아니더라도:

- 장애인 고용
- 원예/농업
- 민화/문화예술
- 제조/포장
- ESG/사회공헌
- AI·디지털 실증

등의 수행역할로 참여할 수 있는지 본다.

`recommended_application_mode`는 가장 현실적인 하나를 표시하되 세 경로 원판정은 모두 보존한다.

## 5. 100점 배점 v1

| 영역 | 최대 |
| --- | ---: |
| A. 신청자격·조건 충족 | 30 |
| B. 태장 사업·전략 연관성 | 20 |
| C. 지원금·현물 경제가치 | 15 |
| D. 실행·준비 가능성 | 15 |
| E. 선정 가능성 | 10 |
| F. 시급성·희소성·전략가치 | 10 |
| 합계 | 100 |

---

## 6. A. 신청자격·조건 충족 — 30점

### 구성 제안

| 항목 | 최대 |
| --- | ---: |
| 법인/신청주체 | 6 |
| 지역 | 6 |
| 업종/사업유형 | 5 |
| 기업규모 | 4 |
| 필수 인증/등록 | 5 |
| 중복·기타 필수조건 | 4 |

### 점수 원칙

- 명확히 충족: 해당 항목 100%
- 조건부 해결 가능: 40~70%
- 확인필요: 원칙적으로 50% 이하 + confidence 하향
- 명확히 불충족: 0

### 직접신청 Hard Fail 보정

`direct_eligibility=ineligible`이고 B/C 경로도 모두 `ineligible`이면:

- overall_score 상한: **49점** 제안
- recommendation: 원칙적으로 `do_not_apply`

직접신청은 불가지만 공동/협력 가능성이 현실적이면 이 상한을 적용하지 않고 B/C 전략가치를 평가한다.

---

## 7. B. 태장 사업·전략 연관성 — 20점

### 사업 상태 가중

- `current`: 가장 높음
- `developing`: 중간
- `planned`: 낮음
- 단순 아이디어: Profile에 없으면 기본적으로 점수 근거로 사용하지 않음

### 최우선 분야

사용자 확정 우선분야:

1. 인건비·고용
2. 문화
3. 원예
4. AI·디지털

해당 분야는 높은 전략점수 후보지만 자격점수를 대신하지 않는다.

### 점수 예시

- 17~20: 태장의 현재 핵심사업/고용유지/직무와 직접 연결
- 13~16: 현재 또는 개발중 사업과 강하게 연결
- 8~12: 확장전략으로 의미 있으나 준비 필요
- 3~7: 간접 연관
- 0~2: 사실상 무관

---

## 8. C. 지원금·현물 경제가치 — 15점

지원금액 하나만으로 계산하지 않는다.

평가요소:

- 태장이 실제 받을 수 있는 금액
- 현물가치
- 자부담
- 지원비율
- 지원기간
- 사업 수행비용

### 금액 구간 초안

현금 + 합리적으로 확인 가능한 현물가치 기준:

- 5,000만원 이상: 기본 12~15점 후보
- 2,000~4,999만원: 10~13
- 500~1,999만원: 7~11
- 500만원 미만: 3~8
- 금액 미확인: 0~6 + verify

### 예외

차량·시설·장비 현물은 금액이 500만원 미만이거나 미확인이라도 태장 운영상 희소성이 크면 별도 전략가치(F)에 반영한다.

높은 자부담은 C 또는 D에서 감점하되 이중으로 과도하게 감점하지 않는다.

---

## 9. D. 실행·준비 가능성 — 15점

평가요소:

- 마감까지 남은 시간
- 준비서류 난이도
- 자격취득 필요
- 컨소시엄 구성 필요
- 자부담 확보
- 수행인력/현장 여력
- 기관문의 필요 정도

구간:

- 13~15: 현재 자료로 충분히 대응 가능
- 10~12: 일부 확인/서류 준비
- 6~9: 상당한 준비 필요
- 1~5: 기한 내 실행 매우 어려움
- 0: 사실상 실행 불가

---

## 10. E. 선정 가능성 — 10점

가장 과장하기 쉬운 항목이다.

### 원칙

공고문에 경쟁률/평가기준/우대요건 등 근거가 없으면 높은 점수를 주지 않는다.

- 8~10: 명확한 우대요건/특화대상과 태장이 강하게 일치
- 5~7: 일반적으로 경쟁 가능하나 특별 우위 불확실
- 3~4: 경쟁력이 약하거나 준비 부족
- 0~2: 구조적으로 선정 가능성이 낮음

근거가 부족하면 5점 부근의 보수적 중립값 + `confidence=low/medium`을 권장한다.

AI가 근거 없이 `선정가능성 80%` 같은 확률을 만들지 않는다.

---

## 11. F. 시급성·희소성·전략가치 — 10점

반영요소:

- 마감 7일 이내
- 전국단위 희소 공모
- 장애인표준사업장 전용/특화
- 차량·시설·장비 현물
- 반복성이 낮은 기회
- 태장의 고용유지/신규직무/매출에 큰 파급

### 주의

`마감이 임박했다`는 이유만으로 좋은 사업이 되는 것은 아니다.

시급성은 `놓치면 손실이 큰 기회`일 때만 점수를 올린다.

---

## 12. 알림 후보 규칙 v1

사용자 기준 Trigger:

- score ≥ 85
- 지원규모 ≥ 500만원
- 차량/시설/장비 현물
- 최우선 분야
- 마감 7일 이내
- 희소 전국공모

### 2단계 판정

#### 1차 Trigger

위 조건 중 하나 이상.

#### 2차 Relevant Gate

다음 중 하나 이상:

- direct eligible/conditional
- joint eligible/conditional
- partner eligible/conditional
- 태장 핵심사업과 높은 전략 연관

A/B/C가 모두 ineligible이고 별도 전략가치도 없으면 알림하지 않는다.

### 알림 등급 제안

- `urgent`: 지금 확인 안 하면 놓칠 가능성이 큼
- `important`: 이번 주 의사결정 필요
- `watch`: 좋은 후보지만 즉시 행동 불필요
- `none`

---

## 13. AI 역할

AI가 하는 것:

- 공고 자연어 조건 구조화
- 애매한 자격 문장 설명
- 공동/협력 참여경로 탐색
- 태장 수행역할 제안
- qualification gap 요약
- 기관에 물어볼 질문 생성
- 전략적 연결성 보완

AI가 최종 권한을 가지지 않는 것:

- 사람의 `신청/보류/제외` 결정
- 원문 없는 자격 단정
- 임의 지원금액 추정
- 임의 선정확률 생성
- 법적/행정적 최종 자격 확정

---

## 14. Evidence 계약

근거는 가능한 한 다음 단위로 남긴다.

- source/document ID
- 페이지/섹션 또는 필드명
- 짧은 근거 요약
- 원문 URL

예:

```text
신청대상: 공고문 3p — 경남 소재 중소기업
자부담: 사업안내 7p — 총사업비 20% 이상
공동수행: 공고문 5p — 수요기업 참여 가능
```

긴 원문을 evaluation에 복제하지 않는다.

---

## 15. Confidence

### high

핵심 자격·기간·지원내용이 공식 원문/구조화 API에서 모두 확인됨.

### medium

대부분 확인됐으나 일부 조건/공동참여/자부담 등 확인 필요.

### low

요약공고만 존재하거나 첨부 누락, 조건 충돌, AI 추론 의존도가 큼.

`low` 평가가 85점 이상 나오면 자동 `urgent`로 바로 보내지 않고 사람 확인을 우선하는 방안을 권장한다.

## 16. 중대한 오판 정의

점수 몇 점 차이보다 아래 오류를 더 심각하게 본다.

### Critical False Positive

- 실제 신청불가인데 `직접신청 가능`으로 표시
- 마감완료 사업을 신청추천
- 필수자격 미보유를 누락
- 중복지원 금지를 놓침

### Critical False Negative

- 실제 태장 직접신청 가능 중요사업을 제외
- 장애인표준사업장 전용 중요지원을 저우선 처리
- 창원/경남/진전면 조건을 잘못 읽어 누락
- 공동/협력으로 참여 가능한 고가치 사업을 직접신청 불가만 보고 버림

Golden Set은 이 두 오류를 우선 줄인다.

| Case | 최소 수 |
| --- | ---: |
| 직접신청 명확 가능 | 3 |
| 직접신청 명확 불가 | 3 |
| 중소기업확인서 등 조건부 | 2 |
| 공동신청 가능 | 2 |
| 협력기관 참여 가능 | 2 |
| 경남/창원 지역조건 | 3 |
| 읍·면/농촌 조건 | 1 |

| 차량/시설/장비 | 2 |
| 고액이지만 태장 부적합 | 2 |
| 마감임박/마감완료 | 2 |
| 동일사업 복수 Source | 2 |

하나의 공고가 여러 Case를 겸할 수 있다.

## 18. Golden Case 기록 형식

각 사례에 다음을 사람이 먼저 기록한다.

- `case_id`
- 사업명
- 기준 공고/첨부
- 평가 기준일
- Taejang Profile version
- expected direct eligibility
- expected joint eligibility
- expected partner eligibility
- expected recommended mode
- expected score range
- expected recommendation
- must-detect gaps
- must-ask questions
- critical evidence
- reviewer notes

### 점수 정답

`87점` 하나를 정답으로 두기보다 허용범위를 둔다.

예:

- expected range 82~90

다만 eligibility와 hard fail은 정확히 맞아야 한다.

---

## 19. 초기 품질 목표 제안

20~30건 pilot에서:

1. Critical False Positive: **0건 목표**
2. Critical False Negative: **0건 목표**
3. 직접/공동/협력 판정 일치율: 90% 이상 목표
4. score expected range 포함: 80% 이상 목표
5. 필수 확인질문 누락: 10% 이하 목표

표본이 작으므로 이 수치를 통계적 정확도라고 과장하지 않는다. Phase 1은 안전한 운영 기준선 마련이 목적이다.

---

## 20. 평가 변경관리

가중치나 규칙을 바꾸면 `ruleset_version`을 올린다.

예:

- `support-radar-rules-v1`
- `support-radar-rules-v1.1`

Golden Set 전체를 재평가하고:

- 좋아진 Case
- 나빠진 Case
- 변경 이유

를 남긴다.

기존 evaluation은 재계산하여 덮어쓰지 않는다.

## 21. Phase 1 AI 자동화 수준

### 우선

- rules-only 계산 가능
- 사람이 공고문 요약/조건을 입력해 평가 가능
- AI 결과 저장 계약 존재

### 후속

실제 Golden Set에서 AI의 이득이 확인되면 `rules_plus_ai`를 자동화한다.

사용자 승인 없는 유료 API 대량 호출은 하지 않는다.

## 22. 사용자 검토가 필요한 핵심 제안

- [ ] 직접신청 불가 + B/C도 불가일 때 49점 상한
- [ ] 6영역 30/20/15/15/10/10 배점
- [ ] `selected probability` 대신 근거기반 0~10 선정가능성 점수
- [ ] low-confidence 고득점은 즉시알림 전 사람 확인
- [ ] Golden Set Critical FP/FN 0건 목표
- [ ] score는 단일 정답이 아니라 허용범위로 검수

승인 전 실제 Rule Engine 구현을 시작하지 않는다.
