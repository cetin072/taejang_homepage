# 공개 홍보 이미지 실패 표시 보완 — 2026-10-26

사용자는 공개 홍보글의 네이버 hero 이미지 ORB 오류와 공통 원인 수정을 승인했다. 실제 사진/콘텐츠 교체·운영 데이터 수정·무단 사진 복제·프록시 보안 우회·검사 제외는 승인하지 않았다. Ready/main/Production 반영은 별도 승인 대기다. 월별 문서 PR530과 분리한다.

## 확인과 변경

- 공개된 브랜치/열린 PR/로컬 작업 폴더에서 같은 목적의 구현을 찾지 못했다. 별도 채팅의 비공개 진행 기록은 Personal Context unavailable로 직접 확인하지 못했다. 독립 브랜치에서 기존 파일을 덮어쓰지 않고 최소 수정한다.
- 이전 CI에서 네이버 `blogthumb.pstatic.net`의 외부 이미지가 Chrome ORB에 차단됐다. 공개된 legacy no-link hero를 카드/상세가 직접 사용하던 경로다. DB 함수/월별 문서 변경 때문에 생겼다는 증거는 없다.
- 공통 ES module은 표시할 이미지와 표시 불가 상태만 계산한다. 네이버 블로그 사진 CDN의 hotlink URL은 직접 요청하지 않고, 원본 데이터는 그대로 보존한다. 이미 빌드에 포함된 공식 아카이브의 로컬 썸네일은 그대로 사용한다.
- 정상 업로드/선택 사진은 계속 표시한다. 첫 선택 사진이 표시 불가여도 다른 사진을 몰래 대표사진으로 대체하지 않는다. 선택된 다른 사진은 기존 첨부 목록에서 유지한다.
- 카드, 초기 서버 HTML(검색/JS 미실행), 클라이언트 상세가 같은 대표사진 표시 정책을 사용한다. 표시 불가 시 실제 사진을 대신한 이미지로 꾸미지 않고 한국어 안내와 본문을 남긴다. 정상 사진의 실제 로딩 실패도 빈 화면으로 지우지 않고 명확히 알린다.
- 외부 연결 글의 참고용 hero는 선택 업로드 사진이 없으면 대표사진으로 쓰지 않는 기존 계약을 유지한다. 별도 제보의 두 번째 글을 네이버 ORB와 같은 문제로 수정하지 않는다.
- 사진 다운로드/복사/업로드, URL·문서 내용·게시 상태 DB 변경, 새 API/프록시/환경변수/보안 예외/의존성 추가 없음. 기존 원문 링크는 있으면 유지한다.

## 검수

합성 Node/SSR/피드 23개 관련 검사가 통과했다. 공개 회귀 147개 통과. PC1440·모바일390에서 네이버 no-request, 정상 사진, 업로드 HTTP500 실패, 서버 선출력 사진 실패, 외부 참고 이미지 정책의 5개 사례씩 10개 흐름을 실제 Chromium으로 검증했다. 정상 이미지는 naturalWidth>0, 실패 시 안내·본문 보존, 가로 넘침 없음, 네이버/참고 이미지 외부 요청 0건을 검사한다. 정상 사진은 합성 응답이며 운영 사진 복구 완료로 보고하지 않는다.

기존 문법 검사는 ES module을 new Function으로 변환하던 부분을 실제 node --check 검사로 보완했다. 기존 public-page-ready/직원앱 Hosted 검사 기준은 완화하지 않았다. Netlify 로컬 build는 성공했으나 이 환경의 네이버 다운로드 실패로 공식 아카이브 43개가 기존 fallback을 사용했다. CI/Preview의 최종 HEAD 결과는 PR 기록을 따른다.

네이버 원본 사진 자체를 사이트에 복구하려면 사용권이 있는 파일을 담당자가 기존 사진 업로드/승인 절차로 등록해야 한다. 이번 수정은 그 운영 콘텐츠 작업을 수행하지 않는다. 72시간 정규 배포와 독립 deploy-now를 변경하지 않는다.
