# Issue #456 — 운영팀장 직원 현장 전수조사 v1

상태: 사용자 개발·운영 반영 승인 (2026-10-14). 기존 직원 목록 PR #452를 재사용하며 별도 전수조사 전용 화면만 추가.

## 현장 업무 동선
직원관리 → **직원 현장 전수조사** → 전체 재직/휴직 직원 한 명씩 선택 → 기존 인사정보·앱 연결·출퇴근 이용 이력 대조 → 얼굴사진 촬영/저장 → 앱 설치·로그인 현장 확인 결과(미확인/완료/미설치/오류) 저장 → 완료/미완료 집계.

전수조사 완료 조건은 ① 인적사항 현장 확인 ② 실제 앱 설치·로그인 확인 ③ 활성 앱 계정 연결 ④ 업무용 직원 얼굴사진 등록이다. `앱 연결`, `푸시 토큰`, `로그인/출퇴근 이용 이력` 각각 단독으로는 **실제 앱 설치 완료의 증거가 아니므로** 현장 확인 상태와 분리한다. 미설치·오류 직원은 미완료 목록에 남긴다.

## 데이터와 권한
- 운영팀장 `promotion_lead`에게 **employee.field_audit_manage** capability를 부여한다. 이는 **전 직원의 비민감 기초명세**와 현장 점검표를 조회·기록하는 용도다. 기존 소속부서 직원관리/RLS와 승격 권한은 확대하지 않는다.
- 운영총괄 `operations_manager`에게는 같은 점검표 조회·수정·상황 요약을 제공한다.
- 입사일·이름·부서·직책·근태 대상의 기본정보 수정은 재직/휴직 중인 **비보호 일반직원**으로 제한한다. 변경은 감사로그에 전후 값을 남기고 stale revision을 거절한다. 임원·관리자·보호 계정의 인사정보 수정은 기존 운영총괄 관리자 경로를 유지한다.
- 업무용 얼굴사진 `employee-private-media/{employee_uuid}/profile/`만 전 부서에 걸쳐 운영팀장이 촬영/등록하도록 기존 Storage helper와 profile photo setter를 좁게 확장한다. `id_photo`(증명서 민감사진)는 관리 권한을 부여하지 않는다.
- 주민번호, 생년월일, 보험상태, 휴대전화, 이메일, 급여, 보호 문서, Auth 세션/토큰을 전수조사 목록에서 반환하지 않는다. 불필요한 민감정보는 메모에 저장하지 않는다.
- `employee_field_audits` 테이블은 PK employee_uuid, RLS 활성, authenticated 직접 SELECT/INSERT/UPDATE 불가, 별도 capability+role 검사 RPC로만 이용한다.
- 직원번호/Person/Employee/Auth/승인선은 유지하며, 이미 처리한 직원 중복복구 PR #454를 재실행하지 않는다.

## 테스트 및 운영 절차
- 합성 Auth 계정으로 격리 Supabase에서 로컬 DB migration replay/pgTAP/RLS/Storage 업로드·서명/직원별 점검·기본정보 교정/권한 거부까지 검증한다.
- PC 및 모바일 390px 렌더링과 뒤로가기/실패 시 입력 유지 점검. 실제 직원 사진·로그인 테스트는 사용자 단말에서만 최종 확인한다.
- 실사용 DB에는 **스키마·권한만** 배포하고, 직원의 현장 확인 결과를 임의로 자동 채우거나 실제 인사정보·사진을 수정하지 않는다.
- Production 웹은 Netlify 릴리스 마커와 정확한 릴리스 커밋으로 별도 배포. 고정 QA가 운영 DB를 공유하므로 실제 직원 정보를 테스트 데이터로 수정하지 않는다.
