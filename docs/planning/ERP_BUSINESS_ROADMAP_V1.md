## 1차 — 기준정보 + 영업·매출 (최초 실제 개발)

**완료 정의 (두 거래 흐름 모두 DB 저장·재조회 + 권한 검증):**

- 고객·공급처·영업자 역할을 가진 **거래처 기준정보** 등록/조회/변경, 중복 방지. 동일 거래처가 여러 역할 가능.
- 거래처 확보/지속 관리 관계와 **담당 영업자** 연결·기간·변경 이력; 향후 재주문에도 연결.
- 상품/용역/원재료/포장재 품목 마스터, 기준 단가(선택), 과세 관련 구분, 선택적 재고관리 플래그. **거래 당시 실제 금액은 스냅샷 보존**.
- 용역: **거래처별 1년 계약**, 업체별 서로 다른 월정액·청구 기준, 월별 매출 생성/확정 및 계약+월 중복 방지.
- 소금: 기업·개인 주문, 쇼핑몰/전화/카톡/발주서 유입, 거래별 가격·수량, 담당 영업자·건별 영업비 조건, **공급처 직배송**·배송 상태. 태장 재고 자동 입출고 없음.
- 매출 기간·거래처·품목 유형·영업자별 목록/상세, 작성중/확정 상태, 서버 권한 검증.
- 기존 **거래처 문서 관리** (월별 공문·견적서·거래명세서·작업결과보고서) 원본과 계산 보존, 매출과 가능한 최소 연결만.
- 테스트: 중복, 담당자 변경 후 과거 거래 불변, 기준 단가 변경 시 과거 매출 불변, 월매출 중복, 직배송, 확정 원본 무단 변경·삭제 차단, 타직원/익명 차단, 근태·연차·급여·홍보 회귀.
- 격리환경 실제 DB CRUD 및 관련 CI/Preview 검증, Draft PR + HEAD/증거 기록.

**명시적 제외:** 2차 실제 수금·지급, 영업비 지급·세무 원천징수, 세금계산서 API, 3차 재고 수불·제조, 4차 전면 마감 처리. 향후 연결에 필요한 거래 ID·관계·원본 이력만 준비; 미래 빈 테이블 대량 생성 금지.

## 2차 — 수금·영업비·공급처 지급 (1차 완료 후)

- 고객 입금(거래별/월 지정일), 부분 입금, 미수금 잔액, 수금 취소/오류 이력.
- 동일 거래에 **고객 수금·공급처 지급·영업비**를 구분해 연결한다.
- 영업자는 거래처 확보 후 지속 관리하며 재주문에도 영업비가 발생할 수 있다. **판매가·영업비는 거래마다 상이하며 고정률 가정 금지**.
- 지급 조건은 **고객 입금 + 필요한 증빙/세금계산서 발행 확인** 후 운영총괄 승인. 승인 후 신속 지급, 목표는 **일주일 이내**.
- **부분 입금 영업비 정책 C 확정:** 거래마다 '전액 입금 후 지급' 또는 '입금 비율에 따른 부분 지급' 선택. 실제 지급·남은 금액 각각 기록.
- 공급처 대금 지급 주기는 **월 1회 지정일 또는 거래별 지급** 선택.
- 실제 계좌이체 등은 외부에서 수행, ERP는 승인·지급 결과·증빙 기록. 자동 송금 없음.
- **최종 승인 A 확정:** 영업비·공급처 지급·환불·월 마감은 **운영총괄 단일 최종 승인**. 대표이사 추가 승인 기본값 없음.
- **3.3% 공제 요청은 세무 적용 확인 전 자동 계산 금지** (대상/소득유형/계약 및 세무사 검토 필요).

## 3차 — 구매·매입·선택적 재고·홈택스 증빙 (2차 완료 후)

- 일반 구매(예: 온라인 쇼핑몰·법인카드): **발주→입고 절차 강제 없이 바로 비용/매입 등록**.
- 고정 매입처가 없어도 일반 공급처/품목/발주/매입 확장 가능.
- 재고관리 대상 품목에 한해 수기 입고·출고·현재고; 태장 직접 보유하지 않는 소금 직배송은 장부상 태장 재고로 잡지 않음.
- **전자세금계산서는 태장 내부에서 홈택스로 직접 발행**(확정). ERP는 발행할 매출/금액 준비 → 발행 후 승인번호·발급일·금액·상태만 원거래에 등록한다.
- **홈택스 처리 방식 C 확정:** 1차 수기 발행 완료 처리, 필요할 때 홈택스 발행 내역 파일을 가져와 거래 대조. 유료 발행 API/홈택스 자동 로그인 초기 제외.
- 기업·개인 주문의 증빙(세금계산서/현금영수증/카드 등)은 거래 성격에 맞게 구분.
- 수정세금계산서·원발행번호 관계와 세무사 검토 경계 보존. 회계·세법 처리 임의 확정 금지.
- 장 사업은 **제조 방식 미확정**. 원재료·포장재·완제품의 기본 품목·재고 확장만 준비, BOM/생산/발효·숙성/제조 LOT/기한 관리 후속 보류.

## 4차 — 취소·반품·정산 변경·마감 통제 (3차 완료 후)

- 주문 배송 전 취소, 전체/부분 반품, 공급처 직배송 회수, 고객 예정 환불/실제 환불 분리.
- 이미 입금/지급된 **원거래·수금·영업비·공급처 지급 기록 삭제/덮어쓰기 금지**, 별도 조정·반환·상계 이력 연결.
- **이미 지급된 영업비 정책 C 확정:** 거래별 다음 영업비에서 상계 / 별도 반환 / 차액 조정·면제 선택, 근거와 운영총괄 승인 기록.
- 용역 계약의 중도 변경은 제품 반품이 아니라 계약·월 매출 조정으로 관리.
- 작성중 직접 수정; **확정 이후 금액·조건 변경은 원본 보존 + 변경 사유/승인/변경 전후값**.
- **월 마감 정책 C 확정:** 기본 잠금 + 통상 오류는 별도 조정. 원기간 정정이 꼭 필요한 경우 운영총괄의 사유 기록·예외 해제·재마감 허용.
- 정정의 회계/세무 귀속은 전문가 검토 없이 자동 결정하지 않음.
- 권한/RLS, 중요 승인·지급·마감/해제 이력 검증. 과거 이력·원본·첨부 보존.

## 공통 보존 경계

- 기존 태장 ERP의 **직원/출근앱/근태 보정/연차/급여/홍보/홈페이지/공지/지원사업/거래처 문서** 및 실제 데이터 보존.
- 태장 ERP 기존 첫 화면은 사용자별 기본 대시보드 확장 방향. 업무수첩은 **임원·지정 직원**, 출근앱은 **전체 직원**. 개인 업무수첩 데이터는 실제 계정·RLS로만 노출. 이는 본 사업 ERP 1~4차와 별도의 이미 진행 중인 통합 과제다.
- 권한 판단은 운영총괄 UI 공통 패턴을 따르되 실제 서버 capability/RLS가 기준; 일반 직원에게 금전/개인정보 권한 부여 금지.
- 신규 코드는 기존 저장소/규칙/PR 확인 후 작은 독립 범위부터. Production DB migration, 주 운영 데이터 대량 변경, main 병합, 운영 배포는 각 단계마다 해당 승인 경계 준수.
