# 삭제·휴지통·복원 UI 통일

2026-10-26 사용자 확정: 공지에서 시작해 태장 업무 메뉴 전체의 **기존 복원 가능한 삭제** UI를 통일한다. 수정·업로드·Draft PR·검사 후 정상 main 병합까지 승인했다. 운영 데이터 변경, migration, 권한 확대, 새로운 영구삭제, 즉시 Production 배포는 제외한다. 배포 정책·workflow는 다른 작업 소유이므로 변경하지 않는다.

## 확인한 계약과 적용 목록

| 메뉴 | 기존 계약 / UI 적용 |
| --- | --- |
| 공지 관리 | archive_notice가 원문을 유지하고 status=inactive, archived_at와 이전 상태를 저장. restore_notice는 이전 상태 복원. 버튼 삭제 / 휴지통 / 복원, 상태 삭제됨·삭제 시각, 검색·복귀·읽기 전용·오류 문구 통일 |
| 일정 관리 | archive_schedule_item / restore_schedule_item / get_archived_recovery_items 재사용. 일반 목록과 별도 휴지통 영역, 삭제·복원·이력 표기 통일 |
| 상시 안내 | archive_staff_guidance / restore_staff_guidance와 같은 기존 휴지통 렌더러 재사용. 직원용 안내와 관리 기능의 권한 경계 유지 |
| 홍보 작성·보완·공개글·발행 관리 | 기존 archive_unpublished_promotion_content / archive_promotion_content 및 restore_promotion_content 유지. 삭제·휴지통·복원, 상태·확인·오류·도움말·접근성 제목 통일. 운영팀장이 삭제한 미발행 글의 복원은 기존처럼 운영총괄이 수행 |
| 홍보 휴지통 | 운영총괄의 기존 복원/영구삭제 분리 유지. 공개 이력이 있는 글의 복원은 숨김 상태이며 자동 재공개를 약속하지 않음. 기존 영구삭제 버튼·별도 제목/확인 입력과 비가역 안내 유지 |
| 직원 관리 | archive_employee / restore_employee와 기존 삭제 직원 조회·계정 연결 화면을 재사용. 직원 휴지통·계정 연결 / 직원 복원 표기. 퇴직·휴직·계정 차단과 구분. 직원 복원을 계정 접근 자동 재허용으로 설명하지 않음 |
| 설정 | 기존 조건부 휴지통 진입 안내 문구만 변경. openArchiveHub API가 없는 현재 구현에서는 해당 블록이 표시되지 않으며 없는 통합 휴지통을 만들었다고 보고하지 않음. 각 모듈의 기존 복원 경로 사용 |

공지 공개 제외는 get_my_notice_list → private_notice_is_current 및 archived_at/상태 계약에 따른 **직원 공지 목록**이다. 일반 공개 홈페이지/정적 배포 소식과 혼동하지 않게 확인 문구를 “직원 공지 목록에서 제외되고 휴지통에 표시됩니다. 나중에 복원할 수 있습니다.”로 조정했다. 이미 열린 화면은 새로 조회할 때 반영되며 즉시 정적 홈페이지 배포를 약속하지 않는다.

공지 휴지통에는 기존처럼 취소·사용 중지 자료도 포함된다. 이를 영구삭제로 바꾸지 않고 각 상태를 구분하며 실제 can_restore가 있는 항목만 복원 버튼을 노출한다. 원문·사진·감사 이력의 저장 계약과 RPC 인자·권한은 변경하지 않는다.

## 유지하는 예외

- 영구삭제: 기존 홍보 기능만 유지. 복원 불가 안내와 별도 확인 절차 유지. 진입 버튼도 `휴지통·영구삭제`로 구분한다.
- 퇴직·휴직, 계정 차단/연결 해제, 게시 취소·사용 중지, 공개 숨김, 월 확정 해제는 각각의 업무 상태여서 삭제로 바꾸지 않는다.
- 개인정보의 암호화 보관, 홈페이지 기본값 복구, 메뉴/대시보드 기본값 복원은 삭제·휴지통 기능이 아니므로 유지한다.
- 구형 메뉴명·보관 버튼을 인식하는 호환 매칭 문자열은 사용자에게 새로 출력하지 않으며 유지한다.
- 배포 workflow·정책·환경변수, DB schema/migration·역할/RLS는 변경하지 않는다.

## 검증과 제한

기존 공지 관리 브라우저에 새 용어의 삭제 → 휴지통 → 복원과 동일 ID RPC 검증을 연결하고, 일정·안내의 기존 공통 렌더러를 합성 데이터로 확인한다. 기존 홍보 fixture는 복원과 영구삭제를 별도로 검증한다. PC·모바일 실행 결과와 정확한 HEAD·CI·Preview·병합 증거는 해당 PR을 최종 기준으로 한다. 운영 공지·직원·설정을 테스트 목적으로 수정하지 않는다.

로컬 빌드는 실행되었으나 외부 네이버 이미지 다운로드가 실패해 기존 fallback 43개를 사용했다. 실제 이미지 성공으로 보고하지 않는다. 자동 승인 검토가 `휴지통·영구삭제`를 `휴지통`으로 줄이는 시도를 구분 상실 위험으로 거절했으며 실행되지 않았다. 안전한 대안으로 영구삭제 표시는 유지하고 검사 기대값만 맞췄다.
