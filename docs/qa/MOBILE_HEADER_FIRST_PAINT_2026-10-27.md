# 모바일 공통 헤더 첫 표시 수정

대상: 사용자가 로고로 홈 이동할 때 메뉴가 잠깐 펼쳐진다고 보고한 문제. 기준 main: 1fd5f81e49452b547d9c66717a5638f18d0b4b4b.

## 원인과 수정
모바일 CSS의 no-JS fallback은 메뉴를 표시하지만, 페이지 하단 site.js가 이벤트를 등록한 뒤에야 js-nav-ready로 접는다. 이전 검사는 site.js 실행 전 링크 순서만 확인해 실제 노출 상태를 놓쳤다.

기존 메뉴 이벤트를 작은 public-navigation.js 한 곳으로 옮겼다. 14개 원본 페이지의 head에서 동기 실행해 DOM을 만들거나 바꾸지 않는 위임 이벤트를 먼저 등록하고 ready 상태를 확정한다. 생성형 기사도 기존 템플릿을 상속한다. site.js는 메뉴 상태를 다시 소유하지 않는다. CSS의 fallback과 공개 링크 순서는 보존한다.

로고·메뉴 링크는 기본 이동을 유지하며 메뉴만 닫는다. Escape 초점 복귀, PC 전환 스크롤 잠금 해제, 뒤로가기 복원 닫힘을 처리한다.

## 검증 범위
공개 회귀 147개, build:netlify 및 관련 runtime smoke/diff 검사 통과. 기존 실제 Chrome 공통 헤더 Gate에 하단 site.js 실행 전 닫힘 상태, 로고 홈 이동, 화면 크기 전환, site.js/초기 navigation 파일 각각의 로딩 실패를 추가한다. 기존 PC·모바일 모든 공통 페이지/메뉴 클릭·글자 확대·JS OFF 검증도 유지한다. 최신 HEAD CI 및 exact-head Preview 결과는 PR에 기록한다.

동일한 공통 헤더의 문제를 대상으로 한다. 홈페이지의 모든 업무·인증·입력 기능이 무결하다는 판정은 아니다. 운영 DB·계정·권한·배포·정책 변경 없음. PR #537의 모바일 카드 크기 작업은 섞지 않는다.

## Preview 로딩 차단 후속

사용자가 완료 후 병합을 승인하고 기존 통과 검사 반복을 제외하도록 지시했다. 실패한 business.html·controller·CSS만 직접 HTTP 진단한 결과 HTTP 200이나 각 요청 약 6초가 걸렸다. 새 외부 동기 controller가 HTML 파싱에 네트워크 의존점을 추가하므로, 공통 원본 파일은 유지하되 게시 빌드에서 root·생성 기사 HTML에 작은 controller를 직접 포함한다. 게시 페이지는 controller 다운로드 없이 동작한다. 새 빌드 변환 전용 테스트와 기존 실패 브라우저 구간을 확인하며, 이전 로컬 전체 회귀는 수동 반복하지 않는다. 필수 CI는 기존 규칙대로 자동 검증한다. 네트워크 지연의 전 원인을 확정하거나 timeout을 늘려 통과시키지 않는다.
