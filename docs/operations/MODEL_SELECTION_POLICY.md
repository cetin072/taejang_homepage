# 태장 Codex 모델·추론 선택 정책

상태: **태장 프로젝트 운영 기준**

공통 기준은 `cetin072/ai-development-system`의 모델 선택 정책을 따른다. 이 문서는 태장 저장소에서 Codex가 작업 시작 때 바로 읽을 수 있도록 프로젝트 운영 규칙을 요약한다.

## 1. 기본 원칙

- 모델은 채팅방이 아니라 **현재 작업 단위**로 다시 선택한다.
- 같은 채팅을 계속 사용해도 새 작업이 시작되면 모델과 추론 수준을 재평가한다.
- 모든 Codex 지시 상단에 `권장 모델`, `권장 추론`, `선정 이유`를 적는다.
- 애매하면 `Terra / Medium`을 기본값으로 한다.
- 이전 작업이 Sol이었다는 이유만으로 다음 단순 작업도 Sol을 계속 사용하지 않는다.
- 작업 중 위험도나 범위가 달라지면 모델을 승급 또는 강등한다.

## 2. Luna

### Luna / Low
- 상태 확인·단순 보고
- 문서 서식·작은 문구 수정
- 파일명·경로·목록 같은 기계적 정리
- 아주 작은 저위험 단일 파일 수정

### Luna / Medium
- 기존 패턴이 명확한 작은 단일 파일 구현
- 작은 테스트 기대값 보정
- 단순 자산 교체·반복 정리

### Luna 금지
다음에는 Luna를 사용하지 않는다.

- 보안
- Auth
- RLS
- 계정·권한
- DB migration
- Production 변경·사고 대응
- 복잡한 원인 분석
- 여러 장기 브랜치 정합화

## 3. Terra

### Terra / Medium — 기본값
- 일반 기능 구현
- UI·UX 수정
- 원인이 비교적 명확한 버그
- 여러 파일의 일반적인 변경
- 테스트 추가
- 기존 구조 안의 API·DB 연동
- 일반 Draft PR 리뷰 반영

### Terra / High
- 여러 모듈 동시 수정
- 원인이 불명확한 버그
- 큰 리팩터링
- 중요한 회귀 위험
- 복합 통합
- 비교적 큰 충돌 해결·브랜치 동기화

## 4. Sol

### Sol / High
- 아키텍처 결정
- 보안·Auth·RLS·권한 설계/검수
- 중요한 DB migration
- 복잡한 시스템 통합
- 중대한 장애 원인 분석
- 대형 merge conflict·장기 브랜치 정합화
- 데이터 무결성·권한·감사로그가 함께 걸린 작업
- 고위험 독립 검수

### Sol / Max — 예외
- Production 사고
- 파괴 가능성이 있는 데이터·권한 변경
- 매우 복잡하고 불확실한 아키텍처·보안 문제
- High로 충분하지 않은 예외 상황

단순 문서, 작은 CSS·문구 수정, 단순 테스트 재실행에는 Sol을 사용하지 않는다.

## 5. 기본 승인 조합

1. `Luna / Low`
2. `Luna / Medium`
3. `Terra / Medium` — 기본
4. `Terra / High`
5. `Sol / High`
6. `Sol / Max` — 예외

`Luna / High`, `Sol / Low` 같은 애매한 조합은 기본 운영 조합으로 사용하지 않는다.

## 6. 자동 판정 순서

1. 보안·Auth·RLS·권한·중요 DB migration·Production·파괴 가능성·복잡한 장기 브랜치 충돌이 있는가?
   - `Sol / High`, 극단적이면 `Sol / Max`
2. 여러 파일·모듈·통합·큰 리팩터링·불명확한 버그인가?
   - `Terra / High`
3. 일반적인 기능 구현·수정·테스트인가?
   - `Terra / Medium`
4. 작고 기계적이며 저위험인가?
   - `Luna / Low` 또는 `Luna / Medium`
5. 애매한가?
   - `Terra / Medium`

## 7. Codex 지시문 헤더

모든 실행 지시는 가능하면 아래 형식으로 시작한다.

```text
권장 모델: GPT-5.6 Terra
권장 추론: Medium
선정 이유: 기존 구조 안의 일반 구현과 회귀 테스트 작업
```

Issue 번호만 전달하는 짧은 지시도 이 헤더를 붙인다.

## 8. 현재 태장 업무플랫폼 예시

`Issue #86`처럼 Auth/RLS·권한·staging 안전성과 장기 브랜치 충돌을 함께 다루는 작업은 `Sol / High`가 적합하다.

반대로 문구 1~2개 수정, 단순 이미지 경로 교체, 테스트 기대값 한두 곳 보정 같은 작업은 Sol을 사용하지 않고 Luna 또는 Terra로 낮춘다.

## 9. 우선순위

프로젝트 고유 `AGENTS.md`, `PROJECT_CHARTER.md`, 관련 기획·보안 규칙이 이 문서보다 더 엄격하면 더 엄격한 기준을 우선한다.
