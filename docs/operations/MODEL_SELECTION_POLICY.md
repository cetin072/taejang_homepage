# 태장 Codex 모델·추론 선택 정책

상태: **태장 프로젝트 운영 기준**

이 문서는 태장 저장소에서 Codex가 작업 시작 때 바로 읽을 수 있도록 모델·추론 선택과 비용 통제 원칙을 정리한다. 프로젝트 고유 `AGENTS.md`, `PROJECT_CHARTER.md`, 확정 기획과 현재 GitHub Issue가 더 엄격하면 더 엄격한 기준을 우선한다.

## 1. 기본 원칙

- 모델은 채팅방이 아니라 **현재 작업 단위**로 다시 선택한다.
- 같은 채팅을 계속 사용해도 새 작업이 시작되면 모델과 추론 수준을 재평가한다.
- 모든 Codex 지시 상단에는 가능하면 `권장 모델`, `권장 추론`, `선정 이유`를 적는다.
- 판단이 애매하면 `GPT-5.6 Terra / Medium`을 기본값으로 한다.
- 이전 작업이 Sol이었다는 이유만으로 다음 작업도 Sol을 유지하지 않는다.
- 작업 중 범위나 위험도가 달라지면 모델을 승급 또는 강등한다.
- 저장소 전체를 반복 재탐색하거나, 변경 범위와 무관한 전체 검사를 매번 실행하지 않는다.

## 2. Luna

### Luna / Low

- 상태 확인·단순 보고
- 문서 서식·작은 문구 수정
- 파일명·경로·목록 같은 기계적 정리
- 아주 작은 저위험 단일 파일 수정

### Luna / Medium

- 기존 패턴이 명확한 작은 단일 파일 구현
- 작은 테스트 기대값 보정
- 단순 자산 교체·반복 정리

### Luna를 사용하지 않는 범위

다음 작업에는 Luna를 사용하지 않는다.

- Auth·RLS·계정·권한
- DB migration
- Production 변경·사고 대응
- 복잡한 원인 분석
- 여러 모듈·장기 브랜치 정합화
- 데이터 무결성이나 보안 경계가 함께 걸린 작업

## 3. Terra

### Terra / Medium — 기본값

- 일반 기능 구현
- UI·UX 수정
- 원인이 비교적 명확한 버그
- 여러 파일의 일반적인 변경
- 테스트 추가
- 기존 구조 안의 API·DB 연동
- 일반 Draft PR 리뷰 반영
- 문서·운영정책 정합화

### Terra / High

- 여러 모듈 동시 수정
- 원인이 불명확한 버그
- 큰 리팩터링
- 중요한 회귀 위험
- 복합 통합
- 비교적 큰 충돌 해결·브랜치 동기화
- **이미 승인된 데이터·권한 계약을 바꾸지 않는 범위의 Auth/RLS/권한 구현·검증**
- staging E2E, 접근제어 회귀검증, 보안 경계 검수

보안·Auth·RLS·권한 작업이라는 이유만으로 자동으로 Sol을 선택하지 않는다. 승인된 계약 안에서 수행할 수 있으면 우선 `Terra / High`를 사용한다.

## 4. Sol — 예외 사용

`Sol / High`는 다음 중 하나가 구체적으로 확인된 경우에만 사용한다.

- `Terra / High`로 반복 검증했지만 원인을 안전하게 확정하지 못함
- 서로 다른 보안·권한 요구가 충돌하여 기존 계약을 보존할 수 있는지 판단이 어려움
- 매우 복잡한 아키텍처·데이터 무결성 문제로 Terra의 분석만으로 안전한 결론을 내리기 어려움
- 중대한 Production 사고에서 Terra로 원인 범위를 좁히지 못함

Sol 사용 전에 가능하면 **왜 Terra / High가 충분하지 않은지 한 줄로 근거를 남긴다.**

단순 문서, 작은 CSS·문구 수정, 테스트 재실행, 명확한 CI 오류 수정에는 Sol을 사용하지 않는다.

## 5. 사람 판단이 모델 선택보다 우선하는 Gate

다음은 모델을 높여서 자동 해결하는 문제가 아니다. Codex는 사용자 승인 없이 의미를 바꾸지 않는다.

- 핵심 아키텍처 변경
- 승인된 데이터 구조·상태 계약 변경
- Auth/RLS/보안/역할/권한의 **의미 변경**
- destructive 또는 중요한 DB migration
- 실제 사용자 계정·권한·민감정보 변경
- 새로운 외부 서비스 도입
- 새로운 비용·유료 API 발생
- 확정 기획·승인선 변경
- 요구사항 충돌 또는 중요한 불명확성
- Ready for review
- `main` 병합
- Production Supabase 변경
- Production 배포

## 6. 기본 승인 조합

1. `Luna / Low`
2. `Luna / Medium`
3. `Terra / Medium` — 기본
4. `Terra / High`
5. `Sol / High` — 예외

## 7. 자동 판정 순서

1. 사람 판단 Gate에 해당하는가?
   - 구현을 멈추고 사용자 판단을 요청한다.
2. 승인된 범위 안이지만 여러 모듈·Auth/RLS·복합 통합·큰 회귀위험인가?
   - `Terra / High`
3. 일반적인 기능 구현·수정·테스트인가?
   - `Terra / Medium`
4. 작고 기계적이며 저위험인가?
   - `Luna / Low` 또는 `Luna / Medium`
5. Terra / High로 반복해도 안전하게 해결하기 어렵다는 구체적 근거가 있는가?
   - `Sol / High`를 예외적으로 검토한다.

## 8. 비용 절약 원칙

- 매 실행마다 저장소 전체를 처음부터 재탐색하지 않는다.
- 기본 탐색 순서는 `AGENTS.md → PROJECT_CHARTER.md → 현재 Goal/Epic → 현재 Issue → 관련 planning → 기존 Draft PR/review`다.
- 현재 Issue와 관련 없는 과거 문서·PR은 필요한 근거가 있을 때만 추가로 연다.
- 변경 직후에는 targeted test를 먼저 실행한다.
- 전체 회귀·CI·Deploy Preview는 완료 또는 중요 gate 직전에 실행한다.
- 이미 통과했고 입력·코드가 바뀌지 않은 hosted mutation이나 고비용 검증을 이유 없이 반복하지 않는다.
- 추가 OpenAI API 결제, 외부 유료 API, 유료 자동화 서비스는 사용자 승인 없이 도입하지 않는다.

## 9. Codex 지시문 헤더

```text
권장 모델: GPT-5.6 Terra
권장 추론: Medium
선정 이유: 기존 구조 안의 일반 구현과 회귀 테스트 작업
```

Issue 번호만 전달하는 짧은 지시도 가능하면 이 헤더를 붙인다. Goal이 안정화된 뒤에는 현재 Goal과 Issue가 충분히 명확하면 `계속해` 수준의 짧은 지시를 허용한다.

## 10. 현재 태장 업무플랫폼 예시

- 일반 문서·운영정책 정리: `Terra / Medium`
- 승인된 TEST-only hosted RLS 검증: `Terra / High`
- RLS 정책의 의미 자체를 바꾸자는 요청: 모델을 높이지 말고 **사람 판단 Gate**
- Terra / High로 반복해도 권한 충돌 원인을 확정하지 못하는 예외 상황: `Sol / High` 재검토
