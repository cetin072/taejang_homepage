# Issue #181 — 직원 실사용 회귀검수

## 2026-09-12 모바일 운영팀장 피드백

실제 Deploy Preview의 운영팀장(`promotion_lead`) 화면에서 `직접 수정`은 검토 카드 안에 있지만, 미발행 글 `삭제`는 별도 `승인 완료·미발행 글 관리`/`홍보 글 관리` 동선에 분산되어 있었다.

확정 UX 기준:

- 운영팀장 사이드바의 홍보 업무는 `홍보 관리`와 `홍보 작성` 중심으로 단순화한다.
- `홍보 관리` 화면에서 검토 대기 글의 미리보기, 직접 수정, 삭제, 보완 요청, 승인, 운영총괄 상신을 한 카드에서 처리한다.
- 별도 사이드바의 `공개글 관리`/`미발행 글 삭제` 중복 진입점은 운영팀장에게 숨기고, 필요한 보조 관리 동선은 `홍보 관리` 화면 안에서 제공한다.
- 미발행 글의 삭제는 기존 `archive_unpublished_promotion_content`를 사용하는 recoverable archive이며 hard delete가 아니다.
- 원문, revision, audit는 보존하고 운영총괄 복구권한을 유지한다.
- 공개 이력이 있는 글의 숨김/재공개/24시간 삭제요청 정책은 바꾸지 않는다.
- 운영총괄의 관리·복구 메뉴는 유지한다.
- 최종 역할별 UX 합격 판정은 실제 운영팀장 계정/실제계정 QA를 사용한다. 기존 역할 미리보기는 권한 빠른 점검용으로만 사용한다.

## 글 종류와 연결 자료

- `글 종류`와 `연결 자료`는 서로 다른 개념으로 취급한다.
- 연결 자료는 `태장 홈페이지`, `태장 공식 블로그`, `태장 공식 유튜브`, `외부 기사·자료`, `연결 없음`으로 구분한다.
- `태장 소식`, `보도자료` 등에서도 필요하면 연결 링크를 입력할 수 있다.
- 글 종류를 바꾸더라도 이미 입력한 URL/연결 자료를 의도치 않게 지우지 않는다.
- 기존 글을 다시 수정할 때 저장돼 있던 링크와 출처 분류를 자동 추정값으로 덮어쓰지 않는다.
- 사용자가 보이는 작성 화면에서 링크를 직접 지운 경우에는 `연결 없음`으로 저장할 수 있어야 한다.

## GPS 실사용 보정

- 80m보다 부정확한 fix가 6초 시점에 있다는 이유만으로 위치 취득을 끝내지 않는다.
- 80m 이내 정확도가 확보되면 즉시 성공한다.
- 최종 위치 취득 제한시간까지 더 좋은 fix를 기다린다.
- 최종 제한시간에도 부정확한 best fix만 있으면 기존 서버 판정으로 전달해 `LOCATION_UNCERTAIN` 계약을 유지한다.
- 위치 공급자가 늦게 timeout/unavailable을 반환하더라도 이미 실제 fix를 하나 이상 확보했다면 그중 best fix를 버리지 않는다.
- permission denied는 기존대로 실패 처리한다.
- 60m geofence와 서버시간 기준은 변경하지 않는다.

## 홈페이지·블로그·유튜브·외부 링크 가져오기

- 같은 `링크 정보 가져오기` 클릭에서 외부 metadata endpoint를 중복 호출하지 않는다.
- 한 번의 응답으로 가져올 수 있는 제목, 설명, 본문, 대표이미지를 참고한다.
- 사용자가 이미 직접 적은 제목·본문은 덮어쓰지 않는다.
- 외부 기사·자료는 원문 전체를 본문에 자동 복제하지 않고 제목·썸네일을 참고한 뒤 태장 측 소개·요약을 직접 작성하는 흐름을 기본으로 한다.
- 자동 가져오기 실패 또는 본문 추출 실패 시 수동 입력을 막지 않고, 직접 작성 후 저장·승인 요청할 수 있음을 화면에 안내한다.
- 외부 fetch의 SSRF/HTTPS/redirect/size/timeout/quota 보안경계는 변경하지 않는다.

## 게시 희망일

- 게시 희망일이 없거나 오늘이면 최종 승인 시 즉시 공개한다.
- 미래 날짜면 해당 날짜 `00:00 Asia/Seoul`에 공개 예정 상태로 둔다.
- due 시각 전에는 public feed/export에서 노출하지 않는다.
- 승인 버튼은 결과가 보이도록 `승인·공개`, `승인·예약`, `승인·다음 검토`로 구분한다.
