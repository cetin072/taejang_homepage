# 태장 홍보업무 운영 매뉴얼 v1

이 문서는 홍보직원과 운영팀장이 PC에서 실제 홍보업무를 처리할 때 사용하는 1차 운영 기준이다.

## 1. 역할과 결재선

### 홍보직원 (`promotion_staff`)

홍보직원은 `태장 소식`을 작성하고, 운영팀장에게서 보완 요청으로 돌아온 자기 글을 수정한다.

기본 흐름:

작성 → 임시저장 → 승인 요청 → 운영팀장 검토 → 보완 요청 시 `보완 요청받은 글`에서 수정 → 재상신

홍보직원은 보도자료 초안을 기본 업무로 맡지 않으며 일반 홍보글을 직접 공개하지 않는다.

### 운영팀장 (`promotion_lead`)

운영팀장은 일반 홍보글의 1차 최종 승인자다.

운영팀장 검토 흐름:

미리보기 → 직접 수정 또는 허용된 미발행 글 삭제 → 보완 요청 또는 승인 → 필요한 경우 운영총괄 상신

일반 홍보글은 운영팀장 최종 승인 시 공개된다.

- 게시 희망일 없음 또는 당일: 즉시 공개
- 미래 게시 희망일: 해당 날짜 00:00 Asia/Seoul 기준 예약 공개

운영총괄에게 상신한 뒤 보완 요청으로 운영팀장에게 되돌아온 글은 운영팀장이 삭제하지 않는다. 해당 글은 수정·보완 후 다시 상신하거나 홍보직원에게 보완 내용을 전달한다.

### 운영총괄 (`operations_manager`)

운영총괄은 전체 운영권한과 복구권한을 가진다.

홈페이지 주요 섹션은 일반 홍보글과 다른 결재선을 사용한다.

운영팀장 수정안 작성 → 운영총괄 결재 상신 → 운영총괄 최종 승인·공개

운영팀장은 홈페이지 주요 섹션을 직접 최종 공개할 수 없다.

## 2. 홍보직원 PC 업무

1. `홍보 작성`으로 들어간다.
2. 신규 글은 기본적으로 `태장 소식`으로 작성한다.
3. 제목과 본문을 작성한다.
4. 필요하면 사진을 첨부한다.
5. 연결 자료가 있으면 링크를 붙여넣는다.
6. 시스템이 태장 홈페이지·공식 블로그·공식 유튜브·외부 기사/자료 여부를 자동 확인한다.
7. 자동 확인이 틀린 경우에만 연결 자료 유형을 직접 수정한다.
8. 필요하면 게시 희망일을 지정한다.
9. 작업 중에는 `임시저장`을 사용한다.
10. 완료하면 `저장 후 승인 요청`을 누른다.
11. 운영팀장이 보완 요청을 하면 `보완 요청받은 글`에서 수정 후 다시 승인 요청한다.

## 3. 글 종류와 연결 자료는 별개

글 종류와 링크 출처는 서로 다른 정보다.

홍보직원 신규 작성은 `태장 소식`을 기본으로 한다. 보도자료 초안은 운영팀장 이상이 담당한다.

`태장 소식`에도 공식 블로그·공식 유튜브·외부 기사 링크를 연결할 수 있다.

연결 자료 유형:

- 연결 없음
- 태장 홈페이지
- 태장 공식 블로그
- 태장 공식 유튜브
- 외부 기사·자료

공식 채널 기준 주소:

- 공식 블로그: `https://blog.naver.com/taejang-official`
- 공식 유튜브: `https://youtube.com/@taejangofficial`

공식 블로그의 개별 게시글 URL과 공식 유튜브 채널의 하위 URL도 공식 채널 자료로 인정한다. 유튜브 `watch`, `shorts`, `youtu.be`처럼 URL 자체에 채널명이 없는 개별 영상은 가져온 페이지의 채널 메타데이터로 태장 공식 채널 소유 여부를 확인한다.

링크 자동 판별은 보조 기능이며, 자동 확인이 틀린 경우에만 직원이 직접 수정한다.

## 4. 링크 정보 가져오기

링크를 입력한 뒤 `링크 정보 가져오기`를 사용할 수 있다.

원칙:

- 이미 직접 입력한 제목·본문은 자동 불러오기가 덮어쓰지 않는다.
- 자동 불러오기가 실패해도 직접 제목·본문을 작성해 저장할 수 있다.
- 원문에서 가져온 원격 사진은 참고용이다. 홈페이지 공개 사진은 직원이 직접 업로드한 사진을 우선한다.
- 외부 기사·자료는 기사 원문 전체를 홈페이지에 복제하는 용도로 사용하지 않는다.
- 외부 기사·자료는 제목·썸네일을 참고하고 태장 측 소개·요약을 직접 작성한 뒤 원문 링크를 연결하는 방식이 기본이다.

## 5. 운영팀장 `홍보 관리`

운영팀장은 `홍보 관리`에서 검토대기 글을 처리한다.

각 글에서 현재 단계에 따라 다음 기능을 확인한다.

- 미리보기
- 직접 수정
- 허용된 미발행 글 삭제
- 보완 요청
- 승인·공개
- 승인·예약
- 승인·다음 검토
- 운영총괄 상신

`삭제`는 물리삭제가 아니다.

운영팀장이 직접 삭제할 수 있는 범위는 **아직 공개되지 않았고, 운영총괄·대표이사 등 상위 결재선에 올라간 이력이 없는 글**이다.

미발행 글 삭제 시:

- 원문 보존
- revision 보존
- audit 보존
- 운영총괄 복구 가능

다음 글은 운영팀장이 삭제할 수 없다.

- 운영총괄에게 상신한 이력이 있는 글
- 운영총괄 검토 후 보완 요청으로 운영팀장에게 되돌아온 글
- 대표이사 결재선까지 올라간 글
- 공개 이력이 있는 글

상위 결재 이력이 있는 글을 폐기해야 하는 경우 운영총괄이 최종 처리한다.

공개 후에는 기존 정책에 따라 숨김, 재공개, 삭제 요청 절차를 사용한다.

## 6. 게시 희망일

게시 희망일은 선택사항이다.

- 미입력: 최종 승인 즉시 공개
- 오늘 날짜: 최종 승인 즉시 공개
- 미래 날짜: 승인 후 예약 상태, 지정일 00:00 한국시간 공개

운영팀장 검토 버튼은 결과를 명확히 보여준다.

- `승인·공개`
- `승인·예약`
- `승인·다음 검토`

## 7. 홈페이지 주요 섹션

다음과 같은 홈페이지 핵심 고정영역은 일반 홍보글과 다르게 처리한다.

예:

- 메인 첫 화면
- 태장 소개
- 주요 사업·하는 일
- 우리의 일터
- 기업 협력·문의
- 기타 홈페이지 핵심 섹션

운영팀장은 수정안 작성과 운영총괄 상신까지만 가능하다.

운영총괄만 최종 승인·공개할 수 있다.

## 8. 문제 발생 시 직원 대응

### 링크 자동 가져오기 실패

업무를 중단하지 않는다.

제목·본문·사진을 직접 입력하고 그대로 저장·승인 요청한다.

### 운영팀장 화면에 삭제 버튼이 안 보임

상위 결재선에 올라간 이력이 있는 글인지 먼저 확인한다. 상위 결재 이력이 있으면 삭제 불가가 정상이다.

### 승인 후 즉시 공개가 부담되는 글

미래 게시 희망일을 지정한 뒤 승인한다.

### 홈페이지 주요 섹션

운영팀장이 직접 공개하려 하지 말고 운영총괄에게 결재 상신한다.

## 9. 1차 완료 판정 기준

홍보직원 PC:

태장 소식 작성 → 링크 자동분류 → 사진 → 임시저장 → 승인 요청 → `보완 요청받은 글` 수정 → 재상신

운영팀장 PC:

검토목록 → 미리보기 → 직접 수정 → 허용된 미발행 글 삭제 → 보완 요청 → 승인·공개/예약 → 운영총괄 상신 → 운영총괄 반송 글 수정·재상신

공통:

- 권한 오류 없음
- 입력 데이터 손실 없음
- 핵심 메뉴가 최초 렌더부터 안정적으로 표시됨
- 자동 가져오기 실패 시 수동 작성 가능
- 상위 결재 이력 삭제 방지가 UI와 서버 모두에서 적용됨
- Node/DB 회귀테스트 GREEN
- 실제 브라우저 대표 흐름 자동검사 GREEN
- Preview 대상 SHA와 배포 자산·함수 경로 확인 완료

위 기계 검증을 먼저 통과한 뒤 실제 기기·실제 업무 데이터에서만 확인할 수 있는 항목을 최종 수용 검수한다.
