## 메인페이지 정보 흐름

메인페이지의 시각적 정보 흐름은 다음 5단계로 구성합니다. 구현상 7개의 시맨틱 섹션과 PHOTO 01~08 구조는 유지합니다.

1. 메인 대표 화면
2. 태장 소개
3. 지금 태장이 하는 일과 실제 일터
4. 활동 기록
5. 협력·문의

`하는 일` 뒤에는 실제 일터 사진과 작업 방식의 핵심만 이어 보여주고, 자세한 설명은 `workplace.html`로 연결합니다. 활동 기록을 협력·문의보다 먼저 보여주어 방문자가 실제 활동을 확인한 뒤 문의하도록 구성합니다.

## 하는 일과 지역사회공헌·ESG 협력

`지역사회공헌·ESG 협력`은 기업·기관과 지역사회에 필요한 활동을 함께 검토하는 협력 방향으로 안내합니다. 현재 실제 사례는 지역 환경정비 활동이며, 복지시설·공공기관·문화 체험 등은 확장 방향으로만 설명합니다.

- 의뢰 내용 확인
- 현장 답사
- 작업 범위와 안전계획 수립
- 인력·물품·사전교육 준비
- 현장 환경정비 수행
- 사진·활동 기록 정리

현재 환경정비 활동은 현장 규모와 조건에 따라 사전 준비가 필요하며, `partnership.html#environment-service`에서 실제 운영 과정을 안내합니다.

## 소식·기록과 활동 상세 경로

공개 메뉴에서는 `태장의 활동`을 별도 메뉴로 두지 않습니다. 행사, 환경·사회공헌, 일터 소식과 외부 채널 기록은 `소식·기록`에서 한 번에 찾도록 합니다.

`activities.html`은 삭제하지 않습니다. 기존 게시물 상세주소인 `activities.html?id=...`가 계속 작동하도록 유지하며, 이 페이지에서 상단 메뉴의 현재 위치는 `소식·기록`으로 표시합니다.

## 홈페이지 문의폼

메인 하단에 `taejang-inquiry` 문의폼을 운영합니다.

문의 유형:

- 모회사·고용 연계
- 기업 업무·건별 프로젝트
- 지역사회공헌·ESG 협력
- 지역·문화 활동
- 제품·행사 문의
- 채용·근무 문의
- 일반 문의

`채용·근무 문의`는 상시 채용을 뜻하지 않으며, 채용 여부와 시기는 문의 시점에 따라 달라질 수 있다고 안내합니다.

코드 상태:

- Netlify Forms용 `data-netlify="true"` 적용
- 이메일 필드 이름 `email` 적용
- 허니팟 `bot-field` 적용
- 개인정보 동의 필수
- 문의 완료 페이지 `/thanks.html`
- 주민등록번호, 장애·건강정보 등 민감정보 입력 금지 안내
- 문의 처리 완료일부터 6개월 보관 후 삭제 안내

Netlify 관리자 화면에서 Form detection과 `taejang2025@naver.com` 이메일 알림을 설정해야 합니다. 정확한 절차는 [`NETLIFY_FORM_NOTIFICATION_SETUP.md`](NETLIFY_FORM_NOTIFICATION_SETUP.md)를 사용합니다.

## 사진과 로고

촬영 현장에서는 [`PUBLIC_HOMEPAGE_PHOTO_SHOOTING_CHECKLIST.md`](PUBLIC_HOMEPAGE_PHOTO_SHOOTING_CHECKLIST.md)를 사용합니다.

공개동의, 직원 안내, 촬영 당일 점검과 철회 처리는 [`PUBLIC_PHOTO_CONSENT_AND_SHOOT_DAY_GUIDE.md`](PUBLIC_PHOTO_CONSENT_AND_SHOOT_DAY_GUIDE.md)를 사용합니다.

고정 파일 경로, 슬롯 연결과 공개 모드 전환은 [`PUBLIC_HOMEPAGE_PHOTO_SLOTS.md`](PUBLIC_HOMEPAGE_PHOTO_SLOTS.md)를 사용합니다.

- 사진은 처음에 넉넉하게 수집하고 시험 배치 후 줄이기
- 공개 승인된 WebP 변환본만 `images/homepage/`에 저장
- PHOTO 01~08은 `photo-01.webp`부터 `photo-08.webp`까지 고정 파일명 사용
- 사진을 넣은 PHOTO 01~08 슬롯만 `assets/js/photo-slots.js`에서 `enabled: true`로 변경
- 메인 최신 소식은 최신 최대 8개까지 각 공개 콘텐츠의 대표사진을 자동 표시하며, PHOTO 09~11 고정 슬롯을 사용하지 않음
- PHOTO 01~08 번호는 검수 단계의 편집 식별자로 유지
- 모바일·PC의 `objectPosition`을 각각 확인
- 공식 공개 직전에 모든 슬롯의 사진·대체 텍스트·크롭 확인
- 최종 확인 후 `PHOTO_REVIEW_MODE = false`로 변경해 번호와 제작 안내 숨김
- 촬영 동의와 홈페이지 공개 동의를 별도로 확인
- 대표·근로자·외부인 사진 공개 동의 확인
- 미확인 사진은 Deploy Preview에도 업로드하지 않기
- 공개동의서와 사진 파일을 분리 보관하고 접근 권한 최소화
- 원본은 공유 드라이브에 보관하고 공개 승인된 변환본만 GitHub 저장소에 반영
- 기업 로고는 네 기업의 공식 원본과 사용 범위가 모두 확인된 뒤 일괄 적용
