## User Scenarios & Testing *(mandatory)*

### User Story 1 - 협력 관계 이해 (Priority: P1)

처음 방문한 기업 담당자는 출자 참여와 일반 상품·용역 협력을 구분하고 태장의 역할을 이해한다.

**Why this priority**: 문장을 줄이더라도 기업 관계와 제도 의미를 정확히 전달하는 것이 우선이다.

**Independent Test**: 승인된 원문과 수정안만 대조해 출자·거래 구분, 기업별 조건 차이와 제도상 주의문이 모두 보존되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 기존 관계 설명, **When** 수정안을 검토하면, **Then** 일반 거래만으로 출자 참여나 제도 효과가 자동 적용된다는 표현은 0건이다.
2. **Given** 현재 공동출자기업과 제도 안내, **When** 수정안과 대조하면, **Then** 기업명·관계·제도 설명·주의문·공식 출처·기준일은 그대로다.

### User Story 2 - 문의 준비 (Priority: P2)

방문자는 문의 목적과 준비할 내용을 쉽게 찾으며, 문의에 불필요한 자료를 준비하지 않는다.

**Why this priority**: 기존 접수 방식으로 이어지는 안내의 이해도를 높인다.

**Independent Test**: 제안 문구에서 문의 목적·희망 시기·회신 수단을 확인하고 회사·기관명이 새로운 필수 조건으로 오해되지 않는지 대조한다.

**Acceptance Scenarios**:

1. **Given** 첫 상담 안내, **When** 방문자가 읽으면, **Then** 완성된 제안서와 민감정보를 첫 문의에 요구하지 않는다.
2. **Given** 기존 두 상담 진입점과 문의 양식, **When** 후속 구현을 검토하면, **Then** 기존 문의 유형·필수 여부·개인정보 안내·접수 동작을 모두 보존한다.

### Edge Cases

- 출자 참여와 사업 협력을 모두 검토하는 기업: 한쪽만 선택해야 한다는 문구를 추가하지 않는다.
- 회사·기관이 없는 방문자: 회사·기관명 제출을 필수로 확대하지 않는다.
- 공동출자기업의 개별 거래·보고 조건이 다른 경우: 동일한 조건을 보장하지 않는다.
- 공개 활동 기록만 확인되는 경우: 유료 용역 실적이나 고객 제출 보고서로 확대하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 승인된 문구 7건과 참여기업 명칭 통일, 통합 관계도, 가벼운 색상·카드·절차 비주얼을 구현하고 관련 검수 후 Draft PR을 작성한다.
- **FR-002**: 기존 6단계 정보 순서와 ‘참여 안내’ 제목, 두 상담 진입점, 공동출자기업 4곳·공통 기록 링크 1개를 보존한다.
- **FR-003**: 제도 본문·주의문·공식 링크·확인일은 수정 대상에서 제외한다. 출자·거래의 구분 및 개별 협의 조건을 완화하지 않는다.
- **FR-008**: 참여기업·태장 두 주체 사이에 출자 참여, 업무 의뢰·상품 구매, 운영·수행 내용 공유를 보여준다. PC는 좌우, 모바일은 상하로 배치하며 글자를 그림에 합성하지 않는다. 기업별 조건 차이와 출자·거래 구분은 설명에 보존한다.
- **FR-004**: 연속된 활동 소개의 동일 설명과 절차·FAQ 중복을 줄이는 안을 제시한다. 핵심 사실이나 기업별 검토 조건은 삭제하지 않는다.
- **FR-005**: 문의 양식의 필수·선택 항목, 문의 유형 전체, 개인정보·동의·보관 안내, 접수·알림·완료 동작은 유지한다.
- **FR-006**: 신규 협력 관계·고용 수치·금액·효과·사업 실적·출자 모집·공개 자료를 추가하지 않는다.
- **FR-007**: 수정안 확인을 받았으므로 실제 화면 변경과 관련 검수·Draft PR을 진행한다. 병합과 운영 배포는 별도 승인 대상이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 제안 7건 전부에 실제 현행 문구, 제안 문구, 변경 이유가 대응한다. FR-001·004에 대응한다.
- **SC-002**: 보존 대상 5묶음(6단계·진입점 / 기업·기록 / 제도·출처 / 활동 근거 / 문의·개인정보 계약)의 의미 변경은 0건이다. FR-002·003·005·006에 대응한다.
- **SC-003**: 사용자가 승인한 항목만 구현하며, 후속 구현에서 페이지 변경과 Draft PR은 허용하되 병합·배포는 0건이다. FR-001·007에 대응한다.
- **SC-004**: 다음 구현 담당자가 같은 명세에서 승인된 문구 7건과 통합 도식, 보존 범위, 승인 순서를 확인할 수 있다. FR-001~007에 대응한다.
